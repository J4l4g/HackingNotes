## Eludir política de ejecución
La *Política de ejecución* no es una medida de seguridad, sino que esta presente para evitar que el usuario ejecute scripts accidentalmente.

Lo primero que tendremos que realizar será consultar la *política de ejecución* actual.
```shell
Get-ExecutionPolicity
```

Para evitar que esta politica nos restrinja podemos evadirlaa usando:
```shell
powershell -ExecutionPolicy bypass
```

```shell
powershell -c <cmd>
```

```shell
powershell -encodedcommand $env:PSExecutionPolicyPreference="bypass"
```

## Herramientas y scripts par eludir las firmas antivirus
### AMSITrigger
>https://github.com/RythmStick/AMSITrigger

Esta herramienta ayuda a identificar que partes de un script de *PowerShell* son señaladas por *AMSI (Interfaz de Análisis AntiMalware)* lo que permite realizar modificaciones precisas para eludir la detección.

Funciona de la siguiente manera: Analiza el script en búsqueda de detecciones *AMSI*, identifica el segmento de código exacto que provoca la detección y permite modificaciones como por ejemplo ofuscación para eludir la detección.

La forma de ejecución es la siguiente:
```shell
AmsiTrigger_x64.exe -i C:\Path\To\Script.ps1
```

### DefenderCheck
>https://github.com/matterpreter/defendercheck

Esta herramienta identifica cadenas de texto y código que podrían activar los mecanismos de detección de Windows Defender.

Funciona igual que la herramienta anterior solo que esta vez analiza archivos o scripts en busca de firmas conocidas por *Windows Defender*, indicándote que patrones o cadenas de texto pueden hacer saltar las alarmas para que sean modificadas mediante cambio de nombres de variables u ofuscar las cadenas de texto, también se pueden invertir las cadenas por ejemplo `Net.Sockets` por `stekcoS.teN`.

La forma de ejecución es la siguiente:
```shell
DefenderCheck.exe Script.ps1
```

### ProtecMyTooling
>https://github.com/mgeeky/ProtectMyTooling

Esta herramienta se encarga de ofuscar los payloads de PowerShell para evitar que los motores de antivirus detecten las firmas.

Funciona de la siguiente manera: Primero ofusca las DLL (Por ejemplo, PowerKatz) lo cifra y después lo codifica, a continuación convierte esa carga útil en una carga ofuscada en *base64* e invierte la cadena para eludir detecciones estáticas.


### Invoke-Obfuscation
>https://github.com/danielbohannon/Invoke-obfuscation

Es una herramienta que ofusca al completo los scripts de PowerShell, incluyendo técnicas para eludir *AMSI*, mediante aleatorización y modificación de cadenas, funciones y la estructura general del script. Siendo este muy útil para ofuscar el código de elusión de AMSI y las cargas útiles de PowerShell.

La forma de ejecución seria la siguiente:
```shell
Invoke-Obfuscation.ps1
```

### Ejemplos de modificación de scripts
#### Invoke-Mimikatz
*Mimikatz* es un script altamente detectable y requiere varias modificaciones significativas para evadir la detección.

Técnicas para la **modificación del script** y evitar su detección:
- Eliminar todos los comentarios predeterminados.
- Cambiar el nombre de las funciones y variables (por ejemplo, `DumpCreds` a `DC`).
- Modificar las llamadas a la API (por ejemplo, `VirtualProtect`, `WriteProcessMemory`).
- Ofuscar el contenido de *PEBytes* de *PowerKatz* y los empaquetadores.
- Implementar funciones inversas para *PEBytes* para evitar detecciones estáticas.
- Agregar comprobaciones de entorno aislado para desperdiciar recursos de análisis (por ejemplo, comprobar si utiliza *VMware* o *VirtualBox*).

**Pasos de ofuscación**
- Cambiar el nombre de los scripts y las funciones (por ejemplo, `Invoke_Mimikatz` a `Invoke-Mimi`)
- Modificar los nombres de las variables para las llamadas a la API detectada.
- Ofuscar la DLL de *PowerKatz* e integrarla en el script (codifica en Base64 y en orden inverso)
- Eliminar advertencias y errores relaccionados con la carga de archivos PE
