## ¿Qué es Active Directory?
**Active Directory** es un servicio de directorio desarrollado por Microsoft para administrar redes de dominio de Windows y es el servicio de administración de identidades mas utilizado en el mundo

Almacena información sobre:
- *Usuarios de Windows:* Información de la cuenta, Privilegios, Perfiles, Directivas.
- *Servidores Windows:* Perfil de administración, Información de red, Impresoras, Recurso compartidos, Directivas.
- *Clientes Windows:* Perfil de administración, Información de red, Directivas.
- *Servicios de firewall:* Configuración, Política de VPN, Política de seguridad.
- *Aplicaciones:* Configuración del servidor, Inicio de sesión único, Información de directorio especifica de la aplicación.
- *Servicios de mail:* Información del buzón, Libro de direcciones.
- *Otros NDS:* Registro de usuarios, Políticas de seguridad.


## Componentes del Active Directory
**Schema** -> Define la estructura del directorio especificando los tipos de objetos (Usuarios, Equipos, Grupos) y sus atributos correspondientes (Nombre de usuarios, Correo electrónico, Identificador de seguridad)

**Query and Index Mechanism** -> Este mecanismo permite búsqueda y organización eficiente de los datos en el directorio. Las consultas normalmente se realizan mediante *LDAP (Lightweight Directory Access Protocol)*

**Global Catalog (GC)** -> Este contiene una replica parcial de solo lectura de todos los objetos del directorio con especial atención a los atributos de uso común, facilitando tareas como la localización de recursos en diferentes dominios.

**Replication Sevice** -> Este servicio sincroniza los cambios entre los controladores de dominio dentro de un dominio y en todo el bosque, garantizando una alta disponibilidad y coherencia en los datos.

## Estructura del Active Directory
![[Pasted image 20260406221200.png]]

Los elementos fundamentales en la estructura jerárquica de Active Directory son: *Forest, Domains and Organizational Units (OUs)*, ya que son los que organizan los recursos y aplica limites administrativos:

**Forest (Bosques)** -> Es la estructura de nivel superior y el limite de seguridad definitivo dentro de Active Directory.
- Un bosque consta de uno o mas dominios que comparten un esquema, una configuración y un catalogo global común.
- Las relaciones de confianza entre dominios en el mismo bosque son automáticas y transitivas.
- Las relaciones de confianza entre bosques deben crearse explícitamente para ellos.
- Las políticas y configuraciones aplicadas a un bosque afectan a todos los dominios que contiene.

**Domains (Dominios)** -> Son los subconjuntos dentro de un *bosque* que sirven como limites administrativos.
- Cada dominio tiene sus propias políticas y servicios de autenticación, pero comparte el esquema y la configuración del bosque.
- Los *dominios* contiene usuarios, ordenadores, grupos y otros objetos.

**Organizational Units (Unidades Organizativas) (OUs)** -> Son los contenedores dentro de un domino que se utilizan para organizar y gestionar objetos.
- Las *Unidades Organizativas* simplifican la delegación de tareas administrativas al permitir un control granular de los permisos.
- Los *Objetos de Directiva de Grupo (GPO)* se pueden aplicar a nivel de unidad organizativa para una gestión centralizada.

## Ataque a Active Directory
**Centrarse en el abuso, no en la explotación** -> Este enfoque hace hincapié en el abuso de configuraciones erróneas inertes y el diseño deficiente en los componentes y relaciones de confianza de Active Directory. 
En lugar de depender de vulnerabilidades y exploits que puedan ser parcheados. Esta metodología es aplicable hasta el punto de poder ser capaz de eludir entornos con los parches de seguridad aplicados

**Uso de herramientas de administración integradas en Windows** -> Todos los ataques se llevaran a cabo utilizando herramientas nativas de Windows, esto al usar herramientas nativas nos garantiza:
- *Mayor discreción* ya que estas herramientas se integran en la actividad habitual del usuario, lo que reduce la posibilidad de detección.
- *Flexibilidad* estas herramientas funcionan eficazmente en entornos sin acceso a sistemas Unix/Linux o donde las herramientas externas están restringidas.

## Componentes físicos del Active Directory
### Controlador de Dominio (DC)
Es un componente crucial en una red basada en Windows, al que se le confía la función de servidor de Servicios de domino de Active Directory (AD DS), asumiendo responsabilidades como:
- *Controlador de domino (DC)* aloja una copia completa del almacén de direcciones de servicios de dominio.
- *Servicios de autenticación y autorización* verificando la identidad de los usuarios y equipos que intentan acceder a los recursos de red determinando el nivel de acceso que se les otorga según las políticas de seguridad establecidas.
- *Replicación de actualizaciones* garantizando la coherencia de los datos en todo el dominio y el bosque.
- *Permite acceso administrativa* facilitando el acceso a estos para poder gestionar cuentas de usuarios, directivas de grupo, recursos de red y otros aspectos de la infraestructura de *Active Directory*.

Cuando un *Controlador de dominio* se ve **COMPROMETIDO** hay consecuencias en la red como pueden ser: Acceso no autorizado, Robo de datos, Interrupción de los servicios y Propagación
de ataques.

## Almacén de datos (AD DS)
El *Almacén de Datos (Data Store) (AD DS)* es el responsable de almacena y administrar la información del directorio siendo esencial para la autenticación de los usuarios, el acceso a servicios y la funcionalidad de las aplicaciones.
Este almacén contiene el archivo llamado *NTDS.dit* con contenido de información confidencial de usuarios, objetos, grupos, hashes y mas.
Los principales propósitos del almacén son:
- *Archivo NTDS.dit* es el archivo que encapsula toda la información del directorio dentro de Active Directory siendo un *Repositorio de información confidencial*, este archivo se encuentra en la carpeta *`%SystemRoot%\NTDS`*

## Componentes lógicos del Active Directory
### Esquema (AD DS)
El *Esquema (Schema)* de servicios de dominio de Active Directory (AD DS) es el que define la estructura, atributos y reglas que rigen el almacenamiento y la administración de objetos dentro del servicio de directorio.
Las principales funciones de este son:
- *Clases de objetos* sirviendo como plantilla para definir los tipos de objetos que se pueden almacenar en el Active Directory.
- *Atributos* representando las propiedades o características de los objetos almacenados en el Active Directory.

## Dominios
Los *Dominios (Domains)* son unidades fundamentales dentro de un entorno de Active Directory, ya que proporcionan servicios centralizados de administración y autenticación para recursos de red.
- Funcionan como **limites organizativos** dentro del *Bosque*, también establecen *limites de seguridad* definiendo el alcance de la autenticación y la autorización para los recursos de red.
- **Relaciones de confianza** son relaciones que se pueden hacer entre dominios dentro o fuera del mismo *Bosque* permitiendo que usuarios y recursos puedan ser accedidos desde otro *Dominio*.
- **Administración del espacio de nombres** teniendo la capacidad de tener un *Sistema de Nombres de Dominio (DNS)* permitiendo a los clientes unidos al dominio localizar los controladores de dominio y otros recursos de red mediante *Nombres completos de Dominio (FQDN)*.

## Árboles
Los *Árboles (Trees)* son colecciones de dominios que comparten un espacio de nombres contiguo y un esquema común.
- *`example.com`*
- *`sales.example.com`*
- *`hr.example.com`*

## Bosques y confianza de dominio
Un *Bosque (Forest)* es la estructura de nivel mas alto en Active Directory, constando de varios arboles de *Dominio* que comparten el mismo *Esquema* pero que no necesariamente comparten un espacio de nombres contiguo.
Las relaciones de confianza permiten a usuarios de in *Dominio* o *Bosque* poder acceder de forma segura a los recursos de otro.
### Tipos de fideicomisos (Trust)
- **Confianza entre dominios padre-hijo**: Se crea automáticamente entre un dominio padre y un dominio hijo.
- **Confianza raíz del árbol**:  Se crea automáticamente cuando se agrega un nuevo árbol de *Dominio*.
- **Confianza externa**: Creada manualmente para conectar dos dominios separados.
- **Confianza de bosque**: Creada manualmente entre *Bosques* para la autenticación entre *Dominios*
