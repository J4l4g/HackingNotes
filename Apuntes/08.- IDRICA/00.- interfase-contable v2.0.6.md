## Medium -> Certificado SSL autofirmado y no confiable en servicio MSSQL
Untrusted Self-Signed SSL/TLS Certificate on MSSQL Service

**CVSS v3.1:** `AV:N/AC:H/PR:N/UI:N/S:U/C:L/I:L/A:N` → **4.8 — Medium / Medio**

#### Threat
**EN:** An attacker positioned on the network path between clients and the database server (e.g., ARP spoofing, DNS poisoning, or a compromised network device) could impersonate the MSSQL service using a forged certificate, since no client can validate the server’s identity against a trusted CA. This could allow interception of database traffic, including credential harvesting in transit.

#### Description

**EN:** The MSSQL instance on port 1433/tcp presents a self-signed X.509 certificate (`CN=SSL_Self_Signed_Fallback`, Subject = Issuer), auto-generated by SQL Server when no CA-issued certificate is configured. Confirmed via nmap’s `ssl-cert` script (native TDS/mssql pre-login support) and a failed `sqlcmd -N` connection with a certificate trust error, showing standard clients cannot validate the server’s identity by default.

#### Recommendations

**EN:** Issue and install a valid certificate from an internal or public CA matching the server’s FQDN, import it into the host’s certificate store, select it in SQL Server Configuration Manager, and restart the service. Enable “Force Encryption” at the instance level and restrict DB access to trusted network segments.

## Medium -> RDP sin NLA obligatorio
Remote Desktop Protocol (RDP) Not Enforcing Network Level Authentication (NLA)

**CVSS v3.1:** `AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N` → **5.3 — Medium / Medio**
#### Threat

**EN:** An unauthenticated attacker with network access to port 3389/tcp can establish a full RDP session before completing authentication, since NLA is not enforced. This increases the service’s pre-authentication attack surface, making the host more susceptible to man-in-the-middle attacks during session negotiation and to any present or future pre-authentication vulnerabilities in the RDP/CredSSP stack. Historically, several critical remote code execution vulnerabilities in RDP (e.g., the “BlueKeep” family, CVE-2019-0708) have required NLA to be disabled as a precondition for exploitation.

#### Description

**EN:** Terminal Services on host `interfase-contable-pentesting.xylemvue.goaigua.com` (3389/tcp) was found to accept RDP connections via security layers other than CredSSP/NLA (RDP Security Layer, SSL and CredSSP with Early User Auth were all negotiated successfully). This was confirmed with nmap’s `rdp-enum-encryption` script and independently verified by connecting with `xfreerdp` forcing the TLS layer (`/sec:tls`), which reached the Windows logon screen without prior NLA authentication.

#### Recommendations

**EN:** Enforce NLA as the only accepted security layer, via GPO (_“Require user authentication for remote connections by using NLA”_) or locally (_System Properties > Remote_). Ensure the host is fully patched against known pre-authentication RDP vulnerabilities, restrict RDP exposure to trusted networks or VPN, and consider MFA for remote access.
