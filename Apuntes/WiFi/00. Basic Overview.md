
# Tipos de autenticación
La autenticación frente a una red WiFi es esencial para proteger las redes inalámbricas y los datos frente al acceso no autorizado.
Los principales tipos son *WEP*, *WPA*, *WPA2* y *WPA3*, siendo cada uno una progresión en laso estándares de seguridad
![[Pasted image 20260728221435.png]]

- *WEP (Wired Equivalent Privacy)* -> Es el protocolo de seguridad WiFi original. Proporciona un cifrado básico, en la actualidad se considera obsoleto e inseguro debido a vulnerabilidades conocidas que lo hacen fácil de vulnerar.
- *WPA (WiFi Protected Access)* -> Fue introducido como una mejora provisional sobre *WEP*, ofreciendo un mejor cifrado a través de *TKIP (Temporal Key Integrity Protocol)*, pero sigue siendo uno de los estándares menos seguros respecto a los nuevos.
- *WPA2 (WiFi Protected Access II)* -> Un avance significativo sobre *WPA* usando una encriptación *AES (Advanced Encryption Standar)*, proporcionando una seguridad robusta. Ha sido el estándar durante muchos años proporcionando una fuerte protección para la mayoría de las redes.
- *WPA3 (WiFI Protected Access III)* -> Es el estándar mas reciente, mejora la seguridad con características como el cifrado de datos de forma individualizada y una autenticación basada en contraseña mas robusta, lo que la convierte en la opción mas segura actualmente.

#### Puntos a evaluar en una red WiFi
- Evaluación de contraseñas para determinar su resistencia y seguridad
- Analizar la configuración para identificar vulnerabilidades
- Analizar la infraestructura de la red en busca de vulnerabilidades
- Pruebas en los dispositivos de los clientes para detectar posibles fallos de seguridad

A continuación de explican mas a detalle estos puntos a evaluar:
1. *Evaluación de contraseñas* -> Esto implica evaluar la solidez y seguridad de as contraseñas o frases de acceso de las redes WiFi. Empleando diferentes tácticas, como ataques de diccionario, ataques de fuerza bruta y herramientas para descifrar contraseñas, para analizar la resistencia de las contraseñas frente a un acceso no autorizado.
2. *Evaluación de configuración* -> Se centra en analizar la configuración de los *routers* y *AP (Access Point)* para identificar posibles vulnerabilidades de seguridad. Esto incluye examinar minuciosamente protocolos de cifrado métodos de autenticación, segmentación de red y otros parámetros de configuración para garantizar que cumplan con las mejores practicas de seguridad.
3. *Evaluación de la infraestructura* -> Esta fase se centra en evaluar la robustez de la infraestructura de la red WiFi. Realizando evaluaciones exhaustivas para descubrir vulnerabilidades en la arquitectura de res, las configuraciones de los dispositivos, las versiones de firmware y los fallos de implementación que podrían ser explotados por atacantes para comprometer la red.
4. *Evaluación de los clientes* -> Se evalúa la seguridad de los clientes WiFi, como portátiles, teléfonos y dispositivos IoT, que se conectan a la red. Implicando buscar vulnerabilidades en el software cliente, los sistemas operativos, controladores inalámbricos y las implementaciones de la pila de red para identificar posibles puntos de entrada para los atacantes.

# Marcos y tipos 802.11
En las comunicaciones 802.11,se utilizan diferentes tramas para diferentes acciones.
Estas acciones forman parte de un ciclo de conexión y son comunicaciones estándar entre las redes inalámbricas. Lo que se busca a la hora de hacer estos ataques es falsificar estas tramas para realizar acciones como desconectar un dispositivo de un cliente te de la red mediante una solicitud de desautorización.

## Trama MAC IEEE 802.11
Todas la tramas 802.11 utilizan la trama MAC. Esta trama es la base de todos los demás campos y acciones que se realizan entre el cliente y el punto de acceso, incluso en redes ad-hoc. Esta trama consta de 9 campos.
- *Frame Control* -> Este campo contiene mucha información como tipo, subtipo, versión del protocolo, to ds (Distribution Sistem), from DS, pedido, etc
- *Duration / ID* -> Este identificador aclara la cantidad de tiempo durante la cual se utiliza el medio inalámbrico
- *Address 1, 2, 3 y 4* -> Estos campos aclaran las direcciones MAC involucradas en la comunicación, pero su significado puede variar según e origen de la trama. Suelen incluir, entre otros, el *BSSID* del punto de acceso y la dirección MAC del cliente.
- *SC* -> EL campo de control de secuencia permite funciones adicionales para evitar la duplicación de frames.
- *Data* -> Este campo es el responsable de los datos que se transmiten del remitente al receptor
- *CRC* -> Es el campo encargado de la comprobación de la redundancia cíclica incluyendo una suma de verificación de 32 bits para la detección de errores

### Tipos de trama IEEE 802.11
- *Management (00) (Gestion)* -> Este marco se utiliza para la gestión y el control, y permiten que el punto de acceso al cliente controlen la conexión activa.
- *Control (01)* -> Estas tramas son utilizadas para gestionar la transmisión y la recepción de tramas de datos en redes WiFi. Se puede considerar como una forma de control de calidad
- *Data (10)* -> Este marco se utiliza para contener los datos que se transmiten

### Subtipos de marcos de Gestión (00)
Principalmente en las pruebas de pentest WiFi, nos centramos en las tramas de gestión. Al fin y al cabo estas tramas son las que se utilizan para controlar la conexión entre el punto de acceso y el cliente, lo cual nos permite analizar cada una de ellas y su función.

A la hora de analizarlos y filtrarlos en *Wireshark*, deberemos de especificar el tipo *00* y los subtipos como se muestran a continuación:
- *Beacon Frames (1000)*
- *Probe Request (0100)*
- *Probe Response (0101)*
- *Authentication Request and Responses (1011)*
-  *Association / Reassociation Request and Responses (0000, 0001, 0010, 0011)*
- *Disassociation / Deauthentication (1010, 1100)*

**1. Beacon Frames (1000)**
También conocidas como *tramas de baliza*, que son utilizadas principalmente por el punto de acceso para comunicar su presencia al cliente o la estación. Incluyen información como los cifrados compatibles, los tipos de autenticación su *SSID* y las velocidades de datos admitidas.

**2. Probe Request (0100) & Probe Response (0101)**
También conocidas como *solicitudes y respuestas de sondeo*, permiten al cliente descubrir puntos de acceso cercanos. Independientemente de si una red esta oculta o no, el cliente envía una solicitud de sondeo con el *SSID* del punto de acceso. Este, a su vez, responde al cliente con información sobre sí mismo.

**3. Authentication Request and Responses (1011)**
Conocida como *solicitudes de respuesta y de autenticación*, el cliente envía solicitudes de autenticación al punto de acceso para iniciar el proceso de conexión. Estos paquetes se utilizan principalmente para identificar al cliente frente al punto de acceso.

**4. Association / Reassociation Request and Responses (0000, 0001, 0010, 0011)**
También conocidas cómo *solicitudes de asociacion y reasociacion*. Tras enviar una solicitud de autenticación y completar el proceso de autenticación, el cliente envía una solicitud de asociación al punto de acceso. El punto de acceso responde con una respuesta de asociación para indicar si el cliente puede asociarse a el o no.

**5. Disassociation / Deauthentication (1010, 1100)**
Conocidos como *marcos de desasociacion y desautenticación*, estas tramas se envían desde el punto de acceso al cliente. Al igual que sus tramas inversas *(asociación y autenticación)*, están diseñadas para finalizar la conexión entre el punto de acceso y el cliente. Estas tramas también contienen un código de motivo que indica por que se desconecta el cliente del punto de acceso. Estas tramas se pueden usar para realizar ataques de *Denegación de servicio*.

# El ciclo de la conexión
Nos centraremos en un ciclo de conexión en la autenticación de *WPA2* básica, estos ciclos siguen la siguiente frecuencia:
- *Beacon Frames*
- *Probe Request and Response*
- *Authentication Request and Response*
- *Association Request and Response*
- *Some from handshake or other security mechanism*
- *Disassociation / Deauthentication*

# Métodos de autenticación
En las redes WiFi existen dos sistemas principales de autenticación que se utilizan comúnmente
- **Open System Authentication** -> Es la forma de autenticación mas sencilla ya que no requiere ningún tipo de credencial a la hora de acceder a ella, es el método de autenticación mas común en redes abiertas.
- **Shared Key Authentication** -> Este método utiliza una clave compartida. En el, como en el cliente, como en el punto de acceso, estos verifican sus identidades mediante un mecanismo de *challenge-response* basado en dicha clave.

![[Pasted image 20260729204316.png]]

>Existen muchos otros métodos, especialmente en entorno *Enterprise* o con protocolos avanzados como *WPA3* y *Enhanced Open*, siendo estos dos los mas frecuentes


## Autenticación de Open System
Este sistema no requiere ninguna clave secreta ni credenciales. Para la autenticación en estas redes se sigue este orden:
 1. El cliente (estación) envía una solicitud de autenticación al punto de acceso para iniciar el proceso de autenticación.
 2. El punto de acceso envía al cliente una respuesta de autenticación, indicando si esta fue aceptada.
 3. El cliente a continuación envía una petición de asociación al punto de acceso.
 4. El punto de acceso responde con una respuesta de asociación indicando si el cliente puede permanecer conectado.

![[Pasted image 20260729210513.png]]

## Autenticación de Shared Key
Esta autenticación si implica el uso de una clave compartida, como su nombre indica. En este mecanismo de autenticación el cliente y el punto de acceso verifican sus identidades mediante el calculo de un *challenge*. Este metodo suele asociarse con *Wired Equivalent Privacy (WEP)* y también con *WiFi Protected Area (WPA)*. Proporcionando un nivel básico de seguridad mediante el uso de una clave precompartida.

![[Pasted image 20260729212713.png]]

### Autenticación vía WEP
1. *Authentication request:* Inicialmente, como suele suceder, el cliente envía al punto de acceso una solicitud de autenticación.
2. *Challenge:* El puntop de acceso responde con una respuesta de autenticación personalizada que incluye un texto de *challenge* para el cliente.
3. *Challenge Response:* El cliente responde con el *challenge* cifrado, que este esta cifrado con la clave *WEP*.
4. *Verification:* El punto de acceso descifra el *challenge* y responde con una indicación de éxito o fracaso.
![[Pasted image 20260729213043.png]]

### Autenticación WPA
Esta metodología utiliza una forma de autenticación que incluye un intercambio de claves de cuatro vías. Remplazando generalmente el proceso de asociación con una verificación mas detallada y en el caso de *WPA3* la parte de autenticación es aun mas compleja para la generación de claves por pares. A grandes rasgos la metodología de esta autenticación es la siguiente.
1. *Authentication Request:* El cliente enviar una solicitud de autenticación punto de acceso para iniciar el proceso de autenticación.
2. *Aythentication Response:* El punto de acceso responde con una respuesta de autenticación, indicando que esta listo para proceder a la autenticación.
3. *Pairwise Key Genaration:* El cliente y el punto de acceso calculan la clave maestra de usuario *(PMK)* a través de la clave pre-compartida *(PSK)* -> Contraseña
4. *Four-Way Handshake:* El cliente y el punto de acceso siguen el protocolo de enlace de 4 vías ![[Pasted image 20260729214447.png]]que incluye el intercambio de valores aleatorios *(nonce)*, la derivación, entre otras acciones para verificar que el cliente y el punto de acceso conocen realmente la clave pre-compartida *(PSK)*

![[Pasted image 20260729214518.png]]

Este tipo de autenticación también es usado por *WPA3*, que es actualmente el estándar de seguridad WiFi mas seguro, introduciendo mejoras significativas con respecto a sus predecesores, incluyendo un cifrado mas robusto y una mayor protección contra ataques de fuerza bruta.
Una de sus características clave es *Simultaneus Authentication of Equals (SAE)*, que remplaza el *Pre-Shared Key (PSK)*.
