# ¿Qué es?
La inyección de comandos en un sistema operativo también se puede conocer como *Sehll Injection*, esta permite a un atacante ejecutar comandos del sistema operativo en el servidor que esta ejecutando una aplicación comprometiendo a la aplicación y sus datos.

# ¿Como ocurre?
Imagínate que una tienda permite ver a un usuario si un articulo esta en stock a través de la siguiente petición URL
```URL
https://insecure-website.com/stockStatus?productID=381&storeID=29
```

Para proporcionar la información del stock la aplicación debe consultar varios sistemas heredados. Esta fue implementada de tal forma que se realiza con una llamada con un comando de shell en el que se indican el ID de producto y el ID de tienda como argumentos
```shell
stockreport.pl 381 29
```

Este comando emite al usuario el stock disponible.
La aplicación no esta implementando ningún tipo de defensa contra la inyección de comandos, por lo que un atacante puede mandar una entrada para ejecutar un comando arbitrario en el campo del ID del producto por ejemplo
```Shell
& echo aiwefwlguh &
```

Lo cal se tramita en la petición de la siguiente forma
```Shell
stockreport.pl & echo aiwefwlguh & 29
```

El `echo` lo que hace es hacer se que muestre el texto de este en la salida de vuelta al usuario junto con un error y al usar, `&` se produce una ejecución de este ya que este carácter se encarga de separar comandos en una shell.

Por lo cual se están ejecutando 3 comandos:
- `stockrepor.pl`
- `echo aiwefwlguh`
- `29`

Lo cual nos devuelve el siguiente error
```Error
Error - productID was not provided
aiwefwlguh
29: command not found
```

# Comandos útiles
A la hora de realizar una inyección de comandos de sistema, deberemos conocer comando básicos para obtener información sobre el sistema operativo

| Funcionalidad             | Linux       | Windows       |
| ------------------------- | ----------- | ------------- |
| Nombre del usuario actual | whoami      | whoami        |
| Sistema operativo         | uname -a    | ver           |
| Configuración de red      | ifconfig    | ipconfig /all |
| Conexiones de red         | netstat -an | netstat -an   |
| Procesos en ejecucion     | ps -ef      | tasklist      |

# Vulnerabilidades que se pueden acontecer
## Inyección ciega (Blind)
En este caso se acontece este tipo de vulnerabilidad cuando el sistema operativo no incluye la respuesta dentro de la respuesta HTTP. Estos obstáculos no quieren decir que no sean accesibles pero si que requieren técnicas diferentes.

Por ejemplo un sitio web donde se permite a los usuarios enviar comentarios sobre el sitio, el usuario lo manda este mensaje tras ingresar su mail y el mensaje con los comentarios, la aplicación en este caso se encarga de mandar un mail junto con el comentario este se generaría de la siguiente forma.
```shell
mail -s "This site is great" -aFrom:peter@normal-user.net feedback@vulnerable-website.com
```

Así se tramitaría el mail sin ningún problema, pero si ene la campo del comentario queremos ejecutar el comando `id` deberemos añadirlo con la concatenación de comandos y escapando el cierre de comillas
```shell
mail -s "This site is great"; id #" -aFrom:peter@normal-user.net feedback@vulnerable-website.com
```

EN este caso al ser una salida que no es devuelta por un `echo` no obtenemos ningún tipo de respuesta pero por ejemplo podríamos identificar si se realiza correctamente uso de retrasos de tiempo

### Retrasos de tiempo (Time-Based)
Un retraso de tiempo lo podemos identificar de diferentes formas, podemos identificando el retraso ejecutando un `ping`
```shell
mail -s "This site is great" & ping -c 10 127.0.0.1 & #" -aFrom:peter@normal-user.net feedback@vulnerable-website.com
```

En este caso lanzamos 10 paquetes ICMP y el tiempo que tarde en responder la aplicación a la respuesta original, rondara los 10 segundos si es interpretado, en al payload tenemos `&` en el primer caso lo concatena con el comentario a enviar y en el segundo caso hace que se ejecute en segundo plano
