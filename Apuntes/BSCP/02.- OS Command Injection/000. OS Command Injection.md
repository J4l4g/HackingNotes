#OS-CommandInjection #BSCP #Teoria 

# ¿Qué es?
La inyección de comandos en un sistema operativo también se puede conocer como *Sehll Injection*, esta permite a un atacante ejecutar comandos del sistema operativo en el servidor que esta ejecutando una aplicación comprometiendo a la aplicación y sus datos.

# ¿Como ocurre?
Imagínate que una tienda permite ver a un usuario si un articulo esta en stock a través de la siguiente petición URL
```URL
https://insecure-website.com/stockStatus?productID=381&storeID=29
```

Para proporcionar la información del stock la aplicación debe consultar varios sistemas heredados. Esta fue implementada de tal forma que se realiza con una llamada con un comando de shell en el que se indican el ID de producto y el ID de tienda como argumentos
```shell
stockreport.pl 381 29
```

Este comando emite al usuario el stock disponible.
La aplicación no esta implementando ningún tipo de defensa contra la inyección de comandos, por lo que un atacante puede mandar una entrada para ejecutar un comando arbitrario en el campo del ID del producto por ejemplo
```Shell
& echo aiwefwlguh &
```

Lo cal se tramita en la petición de la siguiente forma
```Shell
stockreport.pl & echo aiwefwlguh & 29
```

El `echo` lo que hace es hacer se que muestre el texto de este en la salida de vuelta al ususario juinto con un error y al usar, `&` se produce una ejecucion de este ya que este caractyer se encarga de separar comandos en una shell.

Por lo cual se estan ejecutando 3 comandos:
- `stockrepor.pl`
- `echo aiwefwlguh`
- `29`

Lo cual nos devuelve el siguiente error
```Error
Error - productID was not provided
aiwefwlguh
29: command not found
```
