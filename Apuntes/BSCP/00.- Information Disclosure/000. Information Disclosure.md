# ¿Qué es?
El *Information Disclosure (Divulgacion de Información)* es cuando una web revela de forma involuntaria información sensible a sus usuarios.
- Datos sobre otros usuarios
- Datos comerciales
- Datos técnicos sobre la web o infraestructura

Suele ser un punto de partida para exponer una superficie de ataque adicional en las cuales se pueden encontrar otras vulnerabilidades.
Ejemplos que son considerados *Information Disclosure*
- Revelación de nombres de directorios ocultos, su estructura y su contenido a través de un `robots.txt`
- Proporcionar acceso a código fuente a través de copias de seguridad
- Mencionar información sobre la base de datos en los mensajes de error
- Exponer información altamente confidencial
- API Keys en texto claro, direcciones IP, credenciales de bases de datos, etc, en el código fuente
- Insinuar la existencia de ausencia de recursos, nombres de usurarios, etc, a través de del comportamiento de la aplicación

# ¿Cómo surgen?
 Esta vulnerabilidad surge cuando hay la *Incapacidad de eliminar contenido interno publico*, *Configuración insegura del sitio web* o *Diseño defectuoso y comportamiento de la aplicación*

# Explotación
## Cómo encontrar esta vulnerabilidad
A continuación se enumeran diferentes técnicas que nos pueden ayudar a encontrar este tipo de información valiosa

## Fuzzing
Para realizar esta acción se puede automatizar usando la herramienta *Burp Intruder* pudiendo proporcionar varios beneficios:
- Se pueden agregar payloads a los parámetros mientras se usan wordlist
- Se pueden identificar fácilmente las diferencias entre las respuestas identificando el código de estado, tiempos de respuesta y longitudes
- Se pueden filtrar por palabras clave como `error`, `invalid` `SELECT`, `SQL`, etc
- Se puede extraer todo lo filtrado de forma que se nos permita comparar el contenido de elementos interesantes dentro de las respuestas

Para crear filtros avanzados se puede instalar la extensión `Logger++`

## Burp Scanner
Usando esta herramienta la gran mayoría de las veces nos identificara si se encuentra divulgación de información.

## Busqueda de respuestas informativas
Muchas veces la aplicación web por si sola no nos va a mostrar información relevante, por lo cual tenemos que estudiar la forma en la que cambian los mensajes de error fuera de su flujo normal de errores. Deberemos de manipular las entradas, peticiones, etc para extraer datos arbitrarios a través de un mensaje de error.

Un ejemplo muy común es:
Hacer que la lógica de la aplicación intente una acción no valida sobre un elemento especifico de los datos. Por ejemplo, la representación de un valor de un parámetro no valido podría conducir una respuesta de traza de depuración de pila que puede contener detalles interesantes.

# Fuentes comunes de Information Disclosure
## Archivos para rastreadores web
Muchos sitios proporcionan archivos como `robots.txt`, `sitemap.xml` estos archivos a menudo enumerar directorios específicos que pueden contener información sensible, muchas veces no se muestran en la enumeración inicial pero es importante navegar a ellos de forma manual.

## Listado de directorios
Si a la hora de enumerar directorios hay algunos de estos que no deberían de estar expuesto y lo encontramos expuesto con información sensible se puede catalogar como vulnerabilidad.

## Comentarios de los desarrolladores
Muchas veces los propios desarrolladores de la aplicación suelen dejar comentarios en el código para ayudarse entre ellos y poder identificar las funciones y que indica cada parte del código o cambios implementados, se pueden usar por que muchas veces enumeran directorios, información que pueda ser muy relevante.

## Mensajes de error
En los mensajes de error es donde se puede llegar a encontrar la mayor parte de la información, ya que en ellos se suelen nombrar tipo de tecnologías usadas, versiones, tipos de bases de datos, servidores que usa la aplicación, etc.
[[00. LAB - Information disclosure in error messages]]

## Datos de depuración
Durante el proceso del desarrollo de una aplicación en esta se suelen agregar mensajes de depuración que no deberían de salir a producción, en caso de que estos mensajes se muestren pueden contener información como:
- Valores de variables de sesión que pueden ser manipulados a través de la entrada del usuario
- Nombres de host y credenciales para los componentes del back-end
- Nombres de archivos y directorios en el servidor
- Claves utilizadas para cifrar datos transmitidos por el cliente

Estos datos de depuración pueden ser que se encentren en un archivos separado, si un atacante consigue acceder a ellos puede comprender el estado de la aplicación incluso pistas sobre como se pueden manipular las entradas y controlar así la información recibida
[[01. LAB - Information disclosure on debug page]]

## Paginas de cuenta de usuario
Las paginas de cuentas de usuario por si misma ya contienen datos confidenciales los cuales deberían de ver solo el propietario de la cuenta. Pero hay casos en la que en los sitios web se acontecen vulnerabilidades que permiten a los atacantes ver información sobre cuentas de otros usuarios.
Por ejemplo, un sitio web que carga la pagina de cuenta de usuario cargada dependiendo del parámetro `user`
```shell
GET /user/personal-info?user=carlos
```

La mayoría de las paginas web aplicaran métodos preventivos para que el atacante no pueda modificar este parámetro y que así no pueda acceder a información confidencial de otros usuarios. Pero esto muchas veces no tiene la robustez necesaria.

Es posible que un atacante no pueda cargar la pagina del usuario objetivo pero puede ser que consiga obtener información como direcciones de correo electrónico u otros datos relevantes.

Este tipo de vulnerabilidad acontecida se conoce como [[IDOR]] 

## Código fuente de archivos de backup
Si a la hora de analizar la web somos capaces de obtener el código fuente de una aplicación web podremos obtener información muy valiosa ya que se podrán construir ataques de alta gravedad.

También en se puede forzar a que el propio sitio web exponga su código fuente, por ejemplo cuando la web trabaja con archivos como extensiones `.php` esta no muestra directamente el código fuente de este archivo si no que directamente es interpretado. Sin embargo en algunas situaciones se puede engañar al sitio web para mostrar el contenido de este archivo

Por ejemplo, los editores de texto a menudo generan una copia de seguridad temporal mientras se edita el archivo original, estos archivos se suelen indicar con el uso de `~` en el nombre del archivo o la extensión. Solicitar un archivo de código usando una extensión de archivo de copia de seguridad a veces puede permitir leer el contenido del archivo en la respuesta.

Una vez el atacante tiene acceso al código fuente este puede ser un gran paso que capacita a identificar y explotar vulnerabilidades adicionales que de otro modo serian casi imposibles.
[[02. LAB - Source code disclosure via backup files]]

## Configuraciones inseguras
LAs aplicaciones web a veces son vulnerables debido a configuraciones inseguras ya que muchas veces implementan aplicaciones o tecnologias de terceros las cuales no se acaban implementando correctamente.

Tambien puede ser que se olviden desactivar opciones de depuracion en un entorno de produccion. Como por ejemplo el `HTTP TRACE` que es u metodo diseñado para diagfnosticos, sis este se encuentra activado el servidor respondera a solicitudes que utilixzan el metodo `TRACE` pudiendo proporcionar el nombre de cabeceras de autenticacion interna que pueden adjuntarse a solicitudes de proxys internos.
