# ¿Que es?
La *Inyección SQL (SQLi)* es una vulnerabilidad de seguridad web que permite a un atacante interferir en las consultas que realiza una aplicación a la base de datos. Permitiendo a un atacante obtener datos que pertenecen a otros usuarios, o datos a los cuales solo la aplicación puede acceder. El atacante puede modificar, consultar e incluso eliminar estos datos causando cambios persistentes en el contenido o comportamiento de la aplicación.

Estos ataques pueden permitir también al atacante escalarlo llegando a poder comprometer un servidor subyacente u otra infraestructura de back-end.

# ¿Cómo detectarla?
Para detectar esta vulnerabilidad es necesario encadenar o usar un conjunto sistemático de pruebas contra cada punto de entrada en la aplicación, normalmente suelen ser las siguiente pruebas:
- Inclusión en entradas del carácter `'` y buscar anomalías o errores
- Algunas sintaxis especificas de *SQL* que evalué el valor original del punto de entrada y a un valor diferente, buscando diferencias sistemáticas en las respuestas de la aplicación
- Condiciones booleanas como `OR 1=1` y `OR 1=2` y buscar diferencias en las respuestas de una aplicación
- Payloads  diseñados para desencadenar retrasos de tiempo cuando se ejecutan dentro de una consulta *SQL*  y buscar diferencias de tiempos en las respuestas
- Payloads *OAST  (Out-of-Band Application Security Testing)* diseñadas para desencadenar una interacción de red fuera de banda cuando se ejecuta dentro de una consulta *SQL* y monitorear cualquier interacción resultante

# Inyección SQL en diferentes partes de la consulta
La mayoría de las inyecciones ocurren en las consultas `SELECT` en el campo `WHERE`, esta suele ser la mas común, pero también se pueden acontecer en cualquier otra ubicación, como por ejemplo en las declaraciones:
- `UPDATE` dentro de los valores actualizados o en la clausula `WHERE
- `INSERT` dentro de los valores insertados
- `SELECT` dentro de la tabla o el nombre de la columna
- `SELECT` dentro de la clausula `ORDER BY`

# Ejemplos de inyecciones SQL
Hay infinidad de vulnerabilidad, ataques y técnicas de inyección SQL que ocurren en diferentes situaciones, algunos ejemplos comunes pueden ser:
## Recuperación de datos ocultos
Este ataque es donde se puede modificar una consulta *SQL* para devolver resultados adicionales.

Imagina en una aplicación de compra que muestra productos en diferentes categorías, cuando el usuario haga clic en *Categorías* -> *Regalos* su navegador solicitara
```sql
https://insecure-website.com/products?category=Gifts
```

Esto hace que la aplicación realice una consulta *SQL* para recuperar los detalles de los productos relevantes de la base de datos
```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

Esta consulta pide a la base de datos que devuelta
- Todos los detalles *`*`*
- Desde la tabla de *`products`*
- Donde *`category`* sea *`Gifts`*
- Y *`released`* sea *`1`*

La ultima restricción `released = 1` se esta usando para ocultar productos que no se liberan, podríamos asumir que estos productos ocultos se encuentran en `released = 0`
