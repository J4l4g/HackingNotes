# ¿Que es?
La *Inyección SQL (SQLi)* es una vulnerabilidad de seguridad web que permite a un atacante interferir en las consultas que realiza una aplicación a la base de datos. Permitiendo a un atacante obtener datos que pertenecen a otros usuarios, o datos a los cuales solo la aplicación puede acceder. El atacante puede modificar, consultar e incluso eliminar estos datos causando cambios persistentes en el contenido o comportamiento de la aplicación.

Estos ataques pueden permitir también al atacante escalarlo llegando a poder comprometer un servidor subyacente u otra infraestructura de back-end.

# ¿Cómo detectarla?
Para detectar esta vulnerabilidad es necesario encadenar o usar un conjunto sistemático de pruebas contra cada punto de entrada en la aplicación, normalmente suelen ser las siguiente pruebas:
- Inclusión en entradas del carácter `'` y buscar anomalías o errores
- Algunas sintaxis especificas de *SQL* que evalué el valor original del punto de entrada y a un valor diferente, buscando diferencias sistemáticas en las respuestas de la aplicación
- Condiciones booleanas como `OR 1=1` y `OR 1=2` y buscar diferencias en las respuestas de una aplicación
- Payloads  diseñados para desencadenar retrasos de tiempo cuando se ejecutan dentro de una consulta *SQL*  y buscar diferencias de tiempos en las respuestas
- Payloads *OAST  (Out-of-Band Application Security Testing)* diseñadas para desencadenar una interacción de red fuera de banda cuando se ejecuta dentro de una consulta *SQL* y monitorear cualquier interacción resultante

# Inyección SQL en diferentes partes de la consulta
La mayoría de las inyecciones ocurren en las consultas `SELECT` en el campo `WHERE`, esta suele ser la mas común, pero también se pueden acontecer en cualquier otra ubicación, como por ejemplo en las declaraciones:
- `UPDATE` dentro de los valores actualizados o en la clausula `WHERE
- `INSERT` dentro de los valores insertados
- `SELECT` dentro de la tabla o el nombre de la columna
- `SELECT` dentro de la clausula `ORDER BY`

# Ejemplos de inyecciones SQL
Hay infinidad de vulnerabilidad, ataques y técnicas de inyección SQL que ocurren en diferentes situaciones, algunos ejemplos comunes pueden ser:
## Recuperar de datos ocultos
Este ataque es donde se puede modificar una consulta *SQL* para devolver resultados adicionales.

Imagina en una aplicación de compra que muestra productos en diferentes categorías, cuando el usuario haga clic en *Categorías* -> *Regalos* su navegador solicitara
```sql
https://insecure-website.com/products?category=Gifts
```

Esto hace que la aplicación realice una consulta *SQL* para recuperar los detalles de los productos relevantes de la base de datos
```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

Esta consulta pide a la base de datos que devuelta
- Todos los detalles *`*`*
- Desde la tabla de *`products`*
- Donde *`category`* sea *`Gifts`*
- Y *`released`* sea *`1`*

La ultima restricción `released = 1` se esta usando para ocultar productos que no se han lanzado todavía, podríamos asumir que estos productos ocultos se encuentran en `released = 0`

La aplicación no implementa ningún sistema de defensa contra ataques de *Inyección SQL*. Por lo cual un atacante podría construir el siguiente ataque:

```sql
https://insecure-website.com/products?category=Gifts'--
```

Esto se traduce a la consulta *SQL*
```sql
SLECET * FROM products WHERE category = 'Gifts'--' AND released = 1
```

En esta consulta se incluyen los caracteres de comentario en *SQL* `--` al incluirlos en la consulta detrás de una `'` la consulta interpreta que se cierra la sentencia al finalizar en `Gifts` y todo lo que se acontece a continuación se basa en un comentario haciendo que no se incluya `AND released = 1`, Como resultado se obtendrían tanto los productos lanzados como los no lanzados.

También se puede ejecutar de cierta forma en la que se puede hacer que la aplicación muestre todos los productos de cualquier categoría incluyendo categorías de las que no se tiene conocimiento

```sql
https://insecure-website.co,/products?category=Gifts'+OR+1=1--
```

El símbolo `+` se usa para concatenar o sustituir al espacio corriente
Siendo esto una consulta *SQL*
```sql
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--' AND released = 1
```

Esta consulta modificada devuelve todos los artículos que su `category` es `Gifts` o que `1` sea igual a `1` como esta consulta siempre es cierta y siempre se cumple devuelve todos los elementos.

## Evadir la lógica de la aplicación
En los casos en la que la aplicación permite a los usuarios iniciar sesión con nombre de usuario y contraseña el usuario envía las credenciales por ejemplo `wiener` como usuario y de contraseña `bluecheese`, si al consulta es afirmativa entonces el inicio de sesión es exitoso, de lo contrario se rechaza.

En este caso un usuario puede iniciar sesión como cualquier usuario sin la necesidad de una contraseña. Se puede realizar usando usando una secuencia de comentarios SQL `--` para eliminar la comprobación de contraseña en la cláusula `WHERE` 

Por ejemplo queremos acceder como `administrator` y la consulta es:
```sql
SELECT * FROM users WHERE username = '' AND password = ''
```

Como atacante deberemos de omitir la validación de la contraseña introduciendo los siguientes parámetro en el campo de login
```sql
administrator'--
```

Lo que transformaría la consulta en el siguiente campo, permitiéndonos acceder como usuario administrador
```sql
SELECT * FROM users WHERE username = 'administrator'--' AND password = ''
```


## Recuperar datos de otras tablas
En los casos en los que un atacante puede recuperar los resultados de la consulta SQL este mismo atacante puede usar esto para recuperar datos de otras tablas dentro de la base de datos.
Pudiendo usar la sentencia `UNION` con la consulta `SELECT`.

Por ejemplo si una aplicación ejecuta la siguiente consulta con la entrada por parte del usuario del filtro `Gifts`
```sql
SELECT name, description FROM products WHere category = 'Gifts'
```

Un atacante se puede aprovechar de ellos usando `UNION SELECT`
```sql
' UINION SELECT username, password FROM users --
```
